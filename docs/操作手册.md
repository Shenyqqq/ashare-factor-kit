## 2. 端到端主流程

数据流（与 `AGENTS.md` 一致）：

```text
AKShare → data/raw/*.parquet（含退市股）
  → 清洗 clean_ret + 涨跌停 masks（内存）
  → 时点对齐（Point-In-Time，简称 PIT：财务披露日 / 行业面板）
  → IC v2 筛选 → factor_configs YAML
  → Walk-Forward / Dynamic 训练 → factor_scores
  → backtest/quantile.py 分组回测 → results/<tag>/
```

| 步骤 | 做什么 | 典型命令 |
|------|--------|----------|
| Step 0 | 数据已在本地则可跳过下载 | `python run.py --skip-download ...` |
| Step 1 | （可选）更新原始数据 | 去掉 `--skip-download`，或单独跑 `python -m data.download_delisted` |
| Step 2 | 构建 / 缓存因子面板 | `run.py` 内自动；可用 `--rebuild-factor-cache` 强制重算 |
| Step 3 | IC 筛选写白名单 | §3（与训练解耦，先筛再训） |
| Step 4 | 训练打分 + 分组回测 | §4 |

**快速冒烟**（前 100 只股票，仅验证管线能跑通，结果不可当真）：

```powershell
python run.py --sample 100 --mode ridge --horizon 5
```

**生产向一键**（数据已齐、因子 YAML 已就绪）：

```powershell
python run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_top31_pure_ic.yaml `
  --output-dir results\ridge_h5_top31_baseline
```

说明：

- `--horizon`：持仓期（交易日）标签长度，同时映射调仓频率（见 §4.2）。
- `--feature-neutralize`：**默认已开启**（对机器学习 / 动态加权特征做 Barra 风格 + 行业残差化，与 IC「纯 IC」口径对齐）。调试关闭：`--no-feature-neutralize`。
- **默认不要**加：`--position-regime`、非 `ew` 的 `--portfolio-opt`、`--two-stage`（见 §5）。

## 3. 标准 IC 筛选（canonical）

### 3.1 为什么叫 canonical？

持仓期 5（h5）与 20（h20）的生产白名单**必须用同一套 CLI 参数**，否则名单规模/构成不可比（历史上曾出现 h20 未开相关去重、因子数虚高）。相关去重（correlation dedup）**默认已开启**；关闭用 `--no-corr-dedup`（生产勿关）。

术语（首次出现）：

- **信息系数（Information Coefficient，IC）**：截面上因子值与前瞻收益的秩相关（或线性相关），衡量预测力。
- **IC 信息比率（ICIR）**：IC 均值 / IC 标准差，衡量稳定性。
- **Newey-West（NW）t**：对 IC 序列做异方差自相关稳健 t 检验。
- **Benjamini-Hochberg 错误发现率（BH-FDR）**：多重检验校正，控制假阳性。
- **Barra 纯 IC**：把因子对 Barra 风格 + 行业回归取残差后再算 IC，剥离系统性风格敞口。
- **多头/空头贡献（Q1 vs Q5）**：在 Barra pure 同一套残差因子上，先按 pure IC 均值对齐方向（负则翻转），再按截面五分组看 Q5/Q1 相对截面的收益，判断纯 IC 偏多头强、空头弱还是双边（见 §3.3a）。
- **Gram-Schmidt 正交精筛**：在粗筛候选上逐个正交，保留残差仍显著的独立因子（写入 `factors_orth`）。
- **稠密硬门（pure AND）**：入池要求 `|IC_eff| > 0.015` **且** `|ICIR_eff| > 0.30`（合取 AND，勿改 OR）。`--barra` 时二者均来自 **pure IC 序列**（pure ICIR ≠ summary raw ICIR）；无 barra 时退回 raw，仍为 AND。顺序：IC∧ICIR（∧t/FDR）→ **long_share**（默认 `>0.4`）→ corr-dedup →（可选 GS）。
- **long_share 门**：须用符号对齐后的分位分解列（`quantile_decomp`；分组前按 pure IC 均值翻转）。summary 已有则用；历史未对齐产物请重跑 `--barra`，或 `--long-share-csv .tmp/quantile_ls_h5_aligned.csv` 离线合并。`--min-long-share 0` 关闭。
- **衰减因子（标注）**：同持仓期 IC 序列上 `R = |ICIR_recent| / |ICIR_past|`；衰减 iff `(R < 0.50 ∧ |ICIR_recent| < 0.20) ∧ |IC_recent| < 0.010`（**合取 AND**，勿改 OR）。默认近窗 `--decay-recent-months 6`（h5≈26 期）；**仅对稠密/稀疏/新兴入选或观察名单打标**（非全库）。`--barra` 时近窗用 pure IC 序列。**不剔除**，仍可在 `factors` 内警示（实盘谨慎）。
- **风格逆转（标注）**：最近一季内 `mean 1{sign(IC_t)≠sign(mean_IC) ∧ |IC_t|>0.015} > 0.75` → 标「风格逆转」。可与衰减叠加；**不剔除**（实盘近季反向警示；窗口仍为 `--reversal-months` 默认 3）。
- **新兴因子（emerging）**：全样本未过 `|IC|∧|ICIR|` 稠密门，且**最近约半年**（默认 `--emerging-lookback 6` 日历月 → h5≈26 期 / h20≈6 期）**pure** 近窗同时满足：① 近窗 NW-t 经 BH-FDR 显著（校正域=稠密轨**全体被测因子**）；② `|ICIR_recent|≥--emerging-recent-icir`（默认 0.35）；③ lift≥`--emerging-lift-min`（默认 1.5）；④ 默认再要求近 **3 个季度** `|ICIR|` 单调不降且末段>首段（`--emerging-trend`，可用 `--no-emerging-trend` 关）。**默认仅标注观察**（`factors_emerging`），**不**并入主池。禁止 raw 近窗救援；仍做 corr-dedup。
- **新兴 holdout / 偷看**：全样本定池本就有选择偏差；**用评效段（如 2026）定池会双重偷看**。近窗统计可截到 `--emerging-asof 2025-12-31`，或 `--emerging-holdout-months 6`（默认 0=现状）。「三季度增强」减轻但不能消灭偷看；评 2026 时**优先 holdout/asof**。
- **稀疏因子（sparse）**：截面大量无信号（龙虎榜 / 涨跌停 / 开板 / 解禁 / 高管 / 大宗 / 业绩预告等），走独立筛选轨道，不进 dynamic；**无 t/NW-t/FDR**。胜率/触发侧按全样本 `s=sign(mean_IC)` 对齐（负 IC 因子不按盲目 `IC>0` / `f>0`）。胜率/payoff 过线后做 **corr-dedup**（默认阈值 0.70，见下）。
- **触发日截面胜率（payoff_hit）**：稀疏轨主门槛之一。触发侧 `f*s>0`（`s<0` 时为 `f<0`），`mean_t 1{ mean(y|f*s>0) > mean(y) }`；日期与普通 IC / 胜率相同（`ic_series` 全部有效交易日，**非**调仓日子集）；默认 ≥ 0.55。`mean_IC≈0` 时跳过稀疏门。

### 3.2 完整命令（h5 / h20 只改 `--period`）

在仓库根目录、一次只跑一个 period（全池约数小时级，视机器而定）：

```powershell
# h5（持仓约 5 交易日 / 周频标签）
.\.venv\Scripts\python.exe -m research.ic_analysis_v2 --period 5 `
  --barra --save --use-fdr --t-threshold 2.5 --decay

# h20（持仓约 20 交易日 / 月频标签）——同参，只改 period
.\.venv\Scripts\python.exe -m research.ic_analysis_v2 --period 20 `
  --barra --save --use-fdr --t-threshold 2.5 --decay
# 需要 factors_orth（dynamic）时再加 --gram-schmidt
```

| 旋钮 | 生产约定 | 含义 |
|------|----------|------|
| `--barra` | 显式打开 | 用 Barra 纯 IC 做门槛 |
| `--quantile-decomp` | **默认 ON**（随 `--barra`） | Q1/Q5 多头空头贡献；`--no-quantile-decomp` 关闭 |
| `--quantile-y-mode` | `residual` | 分位收益口径：`residual`（y 再残差化）/ `raw`（pure IC 同款 y） |
| `--save` | 显式打开 | 写入 `research/output/` |
| `--use-fdr` | **默认 ON** | BH-FDR 多重检验（**仅稠密轨**） |
| `--t-threshold 2.5` | 2.5 | NW_t / FDR 配套阈值（**仅稠密轨**） |
| `--gram-schmidt` | **默认 OFF** | 正交精筛 → `factors_orth`（显式 `--gram-schmidt` 开启） |
| `--corr-dedup` | **默认 ON** | 截面相关去重；`--no-corr-dedup` 关闭 |
| `--min-long-share` | **默认 0.4** | 符号对齐后 `long_share >` 阈值；`--min-long-share 0` 关闭 |
| `--long-share-csv` | 可选 | 合并/覆盖对齐后 long_share（未重跑 `--barra` 时用） |
| `--decay` | 可选 | 算跨持仓期衰减表（诊断）；**不再**作筛选主门 |
| `--decay-gate` | **默认 ON** | 同持仓期衰减**标注**（合取）；`--no-decay-gate` 关闭 |
| `--reversal-label` | **默认 ON** | 风格逆转**标注**；`--no-reversal-label` 关闭 |
| `--emerging` | **默认 ON** | 新兴因子**观察标注**（不进主池）；`--no-emerging` 关闭 |
| `--sparse-track` | **默认 ON** | 稀疏独立轨道；`--no-sparse-track` 关闭 |
| `--corr` | 默认关 | **仅打印**相关矩阵，不控制去重 |
| `--fresh` | 按需 | 清空本 period 的 checkpoint 后全量重算 |
| `--resume` | 按需 | 从 checkpoint 续跑；**改阈值后不要 resume**（旧 barra_pure 无 pure 序列会自动重算 Barra） |
| `--only-new` | 按需 | **增量 IC**：只算 registry 相对 `ic_series` 缺失的因子；`barra_pure` 指纹匹配时只补新区并 merge；仍重跑 summary/selection |
| `--factors` | 按需 | 只算逗号分隔的因子名并 merge；同上，不清全量 `barra_pure`（指纹失效除外） |
| `--plot-rolling-ic` | 按需 | 滚动 IC 折线 → `research/output/figs/`（复用 ckpt 序列；默认入选或 \|IC\| Top-N；`--plot-rolling-ic-top-n` / `--plot-rolling-ic-window` / `--plot-rolling-ic-names`） |

**增量补算新因子（推荐，勿开整包）：**

```bash
# 注册新因子后：只算缺失名 → merge ic_series → 增量 barra_pure → 重跑 selection/save
python -m research.ic_analysis_v2 --period 5 --barra --save --use-fdr --t-threshold 2.5 --only-new --workers 1 --barra-workers 1

# 或指定名单（已在 checkpoint 中的会跳过）；需要 GS 时再加 --gram-schmidt
python -m research.ic_analysis_v2 --period 5 --barra --save --use-fdr --t-threshold 2.5 --factors A158_NEW1,GTJA_200 --workers 1 --barra-workers 1
```

多轨默认阈值（均可 CLI / `config/settings.py` 覆盖）：

| 门 | 默认 | 说明 |
|----|------|------|
| `--ic-threshold` / `--icir-threshold` | 0.015 / 0.30 | 稠密硬门：**\|IC\|∧\|ICIR\| 合取 AND**；`--barra` 用 pure 序列算二者 |
| `--decay-retention-min` | 0.50 | `R=\|ICIR_recent\|/\|ICIR_past\|` 下限（合取之一） |
| `--decay-retention-min-sparse` | 0.30 | 稀疏轨衰减标注略松 |
| `--decay-recent-icir-max` | 0.20 | `|ICIR_recent|` 上限（合取） |
| `--decay-recent-ic-max` | 0.010 | `|IC_recent|` 上限（合取） |
| `--decay-recent-months` | 6 | 近窗回溯约半年（周频≈26 期 / 月频≈6 期） |
| `--reversal-frac` / `--reversal-months` | 0.75 / 3 | 近一季反向强 IC 占比 → 风格逆转标注 |
| `--reversal-abs-ic` | 0.015 | 风格逆转「强 IC」绝对值门槛 |
| `--emerging-lookback` | 6 | 最近窗口**日历月**（≈半年；内部换算 IC 期数） |
| `--emerging-holdout-months` | 0 | 新兴近窗去掉样本末尾 N 月（评 2026 建议 6） |
| `--emerging-asof` | — | 新兴近窗截止日期（评 2026 优先 `2025-12-31`） |
| `--emerging-trend` | **默认 ON** | 近 3 季 \|ICIR\| 单调不降且末>首；`--no-emerging-trend` 关 |
| `--emerging-recent-icir` | 0.35 | 新兴近窗 \|ICIR\| 门槛（与 FDR/lift/趋势合取；`--barra` 用 pure） |
| `--emerging-fdr-alpha` | 0.05 | 新兴近窗 NW-t 的 BH-FDR 水平（校正域=稠密全体被测因子） |
| `--emerging-lift-min` | 1.5 | 新兴 \|ICIR_recent\|/\|ICIR_past\| 下限（≤0 关闭） |
| `--emerging-recent-ic` | — | **已弃用 no-op**（旧 \|IC\| OR 门已移除） |
| `--sparse-ic-threshold` / `--sparse-icir-threshold` | 0.015 / 0.20 | 稀疏轨 IC **软参考**（默认不硬剔；`--sparse-require-ic` 才硬门） |
| `--sparse-win-rate-min` | 0.56 | 同向 IC 胜率硬门槛（`mean(sign(IC_t)==s)`；全日频 IC） |
| `--sparse-payoff-min` | 0.55 | 触发日截面胜率 `payoff_hit`（触发侧 `f*s>0`；与 IC 同日期） |
| `--sparse-corr-threshold` | 0.70 | 稀疏轨相关去重阈值（与稠密 `--corr-threshold` 独立；受 `--corr-dedup` 开关控制） |
| `--decay-half-life-min` / `--sparse-t-threshold` | — | **已弃用 no-op**（会告警） |

32GB 机器可加：`--workers 1 --barra-workers 1`。

冒烟（勿覆盖生产产物前请先备份或改 period）：`--sample N` 只算前 N 个因子；生产筛选**不要**用 `--sample`。

### 3.3 产物路径

IC `--save` 后（`{p}` = 5 或 20）：

| 产物 | 路径 |
|------|------|
| IC 摘要表 | `research/output/ic_summary_h{p}.csv` |
| 分年 IC | `research/output/ic_yearly_h{p}.csv` |
| Barra 纯 IC 表 | `research/output/ic_barra_pure_h{p}.csv`（开启分位分解时追加多头/空头列） |
| 多头空头贡献表 | `research/output/ic_quantile_ls_h{p}.csv`（仅 `--barra` + 分位分解） |
| 筛选结果 JSON | `research/output/selected_factors_h{p}.json` |
| 分类 Markdown | `research/output/selected_factors_h{p}_categories.md` |
| 覆盖前归档 | `research/output/_archive/`（自动备份旧文件） |

JSON 内关键字段：

- `factors`：稠密轨道入选（普通；含已标衰减/逆转者），给机器学习 / ridge 等用；**不含新兴**。
- `factors_orth`：Gram-Schmidt 后的正交子集（给 **dynamic** 动态加权用；**不含**稀疏/新兴）。
- `factors_sparse`：稀疏轨道入选；经 `--special-factors sparse` 或 `--sparse-from-ic` 注入 ridge，**禁止**进 dynamic。
- `factors_emerging`：新兴观察名单（仅标注；不进 ML 默认白名单）。
- `categories`：主类别（普通 / 稀疏 / 新兴）。
- `labels`：警示标签（衰减因子 / 风格逆转），可叠加，**不剔除**。
- `categories_grouped`：主类别 + 警示标签汇总（衰减/逆转可与主类别重叠）。
- `orthogonalization`：GS 元数据（方法、门槛、剔除数）。
- `meta.config_snapshot`：记录 `barra / use_fdr / t_threshold / corr_dedup / gram_schmidt / decay-gate / emerging / sparse-track` 等。

### 3.3a 多头/空头贡献（Barra pure 路径）

**目的**：判断 Barra 纯 IC 主要来自「多头（Q5）强」还是「空头（Q1）弱」。分解在「越高越好」方向上做。

**口径**（与 pure IC 同日、同控制矩阵）：

1. 每个调仓日，对因子做 WLS：`resid_x = f - [1, Barra, 行业] β`（与 pure IC 的 x 相同；权重=√市值）。
2. 收益侧默认再残差化：`resid_y = y - [1, Barra, 行业] γ`（`--quantile-y-mode residual`）；也可选 `raw` 直接用 pure IC 的 forward return。
3. **IC 方向对齐**：若该因子时序 pure IC 均值 < 0，对用于分组的 `resid_x` 取反（pure IC 序列本身不取反），使「高分 = 预测收益更高的一侧」。
4. 对对齐后的 `resid_x` 做五分位（`qcut` on rank，ties 用 first；bins 不足则跳过该日），算各组等权 `resid_y`（或 raw y）。Q5=名义多头，Q1=名义空头。
5. 单日：`多头超额 = Q5 - CS_mean`，`空头贡献 = CS_mean - Q1`，`spread = Q5 - Q1`，`long_share = 多头超额 / (多头超额+空头贡献)`（分母>0）。
6. 时序平均后：`long_share > 0.65` → **多头主导**；`< 0.35` → **空头主导**；其间 → **双边**；对齐后合计超额仍≤0（数值病态）→ **无效**。**不要**因负 IC 未翻转而标无效。

**注意**：仓库里 Barra pure IC 本身是 `Spearman(resid_x, y_raw)`（残差化的是因子，不是收益）。分位分解默认对 y 再残差化，是为了用风格中性收益解释多空来源；若要与 pure IC 的 y 完全一致，用 `--quantile-y-mode raw`。列名未变，但负 IC 因子的 Q5/long_share/多空来源按对齐后口径；需重跑 `--barra` IC 才会更新已落盘 CSV。

**解读**：

| 多空来源 | 含义 | 实盘提示 |
|----------|------|----------|
| 多头主导 | 对齐后高分组相对截面赚得多 | 更适合做多/选股增强 |
| 空头主导 | 对齐后低分组相对截面亏得多 | IC 多来自「避开差票」；做多组合可能偏弱 |
| 双边 | 两侧都有贡献 | 多空对冲叙事更完整 |
| 无效 | 对齐后多空合计仍无正超额 | 勿解读方向（非「负 IC」同义） |

开关：`config/settings.py` 中 `IC_QUANTILE_DECOMP` / `IC_QUANTILE_Y_MODE` / `IC_QUANTILE_BILATERAL_LO|HI`；CLI `--quantile-decomp` / `--no-quantile-decomp` / `--quantile-y-mode`。

**新兴 corr-dedup 方案**：候选按近窗 \|ICIR\| 降序；与已保留稠密因子及已选新兴做 IC 序列相关去重（优先 pure 序列）；仅影响 `factors_emerging`，不改主池。

**稀疏 corr-dedup 方案**（胜率/payoff 过线后、写入 `factors_sparse` 前）：
1. 优先与稠密一致：截面 Spearman + `--corr-method`（默认 `max`）聚合（复用 `_pairwise_corr_matrix` / `_aggregate_corr`）；
2. 若截面矩阵为空或不稳定（稀疏触发日重叠不足 `min_periods`，硬套截面会静默跳过去重）→ **fallback** IC 序列 Pearson 相关（与 emerging / `--raw-select` 同口径）；
3. 候选按 \|ICIR\| 降序；`|corr| > --sparse-corr-threshold`（默认 0.70）时剔除较弱者，理由写入 `excluded`；
4. 受 `--corr-dedup` / `--no-corr-dedup` 统一开关控制；仅影响 `factors_sparse`，不改稠密主池。

#### 入选类别定义

| 类别 | 含义 |
|------|------|
| 普通因子 | 稠密池全样本过线（IC/ICIR/t/FDR/corr）→ `factors` |
| 稀疏因子 | 语义稀疏池：同向 IC 胜率 + 触发日截面胜率过线（按 `sign(mean_IC)`；无 t/FDR）→ 再 corr-dedup |
| 新兴因子 | 全样本未过 IC/ICIR 门 + 近窗 FDR∧ICIR∧lift；**仅观察**，不进主池 |
| 衰减因子 | 警示标签：R 塌缩 ∧ 近期 ICIR 弱 ∧ 近期 \|IC\| 弱；**仍可在 factors 池** |
| 风格逆转 | 警示标签：近一季多数强 IC 与全样本符号相反；可与衰减叠加 |

### 4.2 `--horizon` 与调仓频率

实现：`utils/rebalance_dates.py::horizon_to_rebalance_freq` + `get_rebalance_dates`。

| `--horizon` | 含义（标签） | 映射的调仓频率 | 实际调仓日 |
|-------------|--------------|----------------|------------|
| 3 | 超短（研究用） | `3D` | 桶内最后交易日 |
| **5** | 约一周持有 | **`W-FRI`（周频）** | 该周最后一个有行情的交易日 |
| 10 | 约双周 | `2W-FRI` | 同上 |
| **20** | 约一月持有（标签） | **`ME`（自然月）** | **该月最后一个交易日**（已修日历 bug） |
| 60 | 约一季 | `ME` 同类月频映射 | 月末最后交易日 |

要点：

1. **h5 ≠「每 5 个自然日」**，而是「约 5 日前瞻收益标签 + **周频**调仓」。
2. **h20 ≠「每 20 个交易日调仓」**，而是「约 20 日标签 + **真·月末**调仓」。一个月交易日常约 20～22，只是近似。
3. 调仓日取 **`groupby`/`resample` 桶内最后一个真实交易日**，不再把周末/假日当调仓日（历史「ME bug」：用日历月末虚拟日导致整月错位/点数偏少）。**修日历之前的月频（h20）回测结果不可与修后结果直接对比。**

## 5. 可选功能（默认关闭）

### 5.1 仓位体制 `--position-regime`

- **做什么**：用市场趋势 / 波动 / 广度合成 `target_exposure ∈ [e_min, 1]`，在分组回测里缩放**非基准** track 的收益（现金收益记 0）。解决「买多少」，不解决「买谁」。
- **何时用**：验证「中等选股 + 降仓避险」的**策略**夏普；不要当作截面 alpha 的证明。
- **默认**：关闭时与旧实验路径 bit-identical。
- 文档：[POSITION_REGIME.md](POSITION_REGIME.md)。

```powershell
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_top31_pure_ic.yaml `
  --position-regime `
  --output-dir results\ridge_h5_posreg

# 强制半仓（覆盖规则合成）
# ... --position-regime --force-exposure 0.5
```

别名：`--pos-regime`。产物含 `position_exposure_*.csv` / `position_regime_*.csv`；tag 后缀 `_posreg`。  
已退役：`--regime-cs`、`--no-regime`、`--ridge-drop-regime`（现为 no-op，可省略）。

### 5.2 组合优化 `--portfolio-opt`

- **做什么**：在**已选**股票集合（Q 分位 / Top-N）上分配权重；**不负责选股**。
- **默认**：`ew`（等权），与历史路径一致。
- **何时用**：对照得分加权 / 逆波动等；小资金优先 `ew` / `rank` / `invvol`。`mv` / `rp` 仅作消融。
- 文档：[PORTFOLIO_OPT.md](PORTFOLIO_OPT.md)。

```powershell
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_top31_pure_ic.yaml `
  --portfolio-opt invvol --max-weight 0.1 --top-n 30 `
  --output-dir results\ridge_h5_invvol
```

可选值：`ew` | `score` | `rank` | `mv` | `invvol` | `rp`。非 `ew` 时 tag 后缀 `_opt{method}`。可与 `--position-regime` 叠加：先优化 invested book（权和=1），再按敞口缩放收益。

### 5.3 两段式 `--two-stage`

- **做什么**：阶段 1（S1）全市场 Walk-Forward 打分 → 每期取 S1 截面 top 分位池（默认 `--stage2-pool-frac 0.2` = **Top20%**）→ 阶段 2（S2）仅用历史「曾在池内」样本；**每个历史日在当日 S1 池内**对 label 与特征做 `winsor(1%/99%) → cs_zscore`，再拼接拟合 Ridge MSE；推理日对当日池内特征做同样变换后预测 → **有分日池外写回 `-inf`**（避免 `qcut`/基准宇宙缩成池内；未拟合暖机日仍为全 NaN）。实现：`models/wf/two_stage.py`。
- **与单段 Q5 对照**：全市场五分位下 Top20% ≈ **Q5**，故二段**池内等权基准**在同一可交易宇宙与成本口径下，理论上应接近单段 **Q5**——用来验 bug / 对照，不是业绩承诺。
- **口径**：样本仍为 S1 TopK%；标签与特征均为**池内**截面变换（不是全市场 raw / 不是多日混做一次 zscore）。若开了 `--feature-neutralize`，顺序为：全局 Barra+行业残差化 → S2 再在池内 winsor→zscore。
- **一级 cache（universe only）**：完整 `--two-stage`（或显式 `--save-stage1-cache`）会写出 `results/<tag>/stage1_cache/`：
  - **存**：`s1_scores.parquet`、`s1_pool_mask.parquet`、`meta.json`（horizon、factor-config 路径/哈希、sparse、feature_neutralize、pool_frac、调仓日、产出时间等）
  - **不存**：池内特征 X、标签 y（二级换因子池/loss 时用 cache 的股票×日期 universe，按当前 YAML 现算并在池内 winsor→zscore）
  - 换一级模型或一级 YAML **必须换 cache**（看 `meta.factor_config_hash` / tag）。
- **何时用**：对照「头部再精排」是否改善 Top-N；**不是**默认生产路径。
- **警告（h5 实测）**：同因子 + event 下，旧口径两段式相对单段 ridge **明显更弱**（例：样本外 ICIR 从约 0.84 降到约 0.04；Top100 夏普约 0.75 → 0.41）。新池内 zscore / Top20% 口径需重新对照；在未验证前**不要默认开启**。
- 不加 `--two-stage` 时**不会**进入两段路径，不影响普通回测。

```powershell
# 完整二段（默认 pool=0.2，并写出 stage1_cache）
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_top31_pure_ic.yaml `
  --special-factors event --feature-neutralize `
  --two-stage --stage2-pool-frac 0.2 --top-n 100 `
  --output-dir results\ridge_h5_twostage

# 只跑一级并强制落 cache（供后续换二级因子）
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_top31_pure_ic.yaml `
  --feature-neutralize --save-stage1-cache `
  --output-dir results\ridge_h5_s1_only

# 从 cache 跳过 S1，用「当前」factor-config 现算二级特征跑 S2
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_stage2.yaml `
  --feature-neutralize `
  --two-stage --stage1-cache results\ridge_h5_twostage\stage1_cache `
  --top-n 100 --output-dir results\ridge_h5_s2_from_cache
```

### 5.4 特殊因子 `--special-factors`

- **做什么**：在 YAML 白名单过滤**之后**，把不必经 IC 白名单的因子 pack **强制注入**训练/打分（IC 筛选路径不变）。
- **默认**：注入因子 `skip_neutralize=True`（开特征中性化时豁免 Barra+行业残差）。
- **`--mode dynamic` 禁止注入**：会 warning 并忽略；`blend-dynamic` 的 dynamic 半边同样拒绝。稀疏/事件包只给 ridge / 树等 ML 路径。
- 文档：[SPECIAL_FACTORS.md](SPECIAL_FACTORS.md)。

| Pack | 内容 | 说明 |
|------|------|------|
| `event` | 如 `业绩预告_超预期` | 事件层；旧 `--event-overlay` 已弃用但仍可用 |
| `size` | `对数市值` / `市值分位` / `市值风格对齐_*` | 市值 alpha；也可写进 YAML，inject 是为了不依赖过线 |
| `sparse` | 龙虎榜/涨跌停/开板/解禁/高管/大宗/业绩预告等 | IC `factors_sparse`；注入时**方差对齐**（供 ridge L2） |

**方差对齐（variance alignment）**：稀疏列堆叠后方差常 ≪ 1，Ridge 的 L2 会压死系数。注入时缩放  
`x' = x * (target_std / std(x_finite))`，默认 `target_std=1.0`（与截面 z-score 后稠密因子同量级）。树模型无需额外处理。

```powershell
# 事件
--special-factors event

# 市值
--special-factors size

# 稀疏（全量语义池；生产更推荐从 IC JSON 取入选名）
--special-factors sparse
--sparse-from-ic research\output\selected_factors_h5.json

# 组合；或写具体因子名
--special-factors event,size,sparse
--special-factors 对数市值,市值分位
```

别名：`--inject-factors`。tag 后缀如 `_event`、`_size`、`_sparse`。

**市值 vs Barra 纯 IC**：在 Barra 纯化后，`对数市值` / `市值分位` 等纯 IC 常接近 0（风格已被控掉）。若仍要用市值信号，用 `--special-factors size` 并接受「非纯 alpha」叙事，或做独立消融，勿与「纯 IC 过线名单」混为一谈。

### 5.5 SHAP 因子贡献 `--shap`

- **做什么**：在 Walk-Forward **最近若干预测日**上，用**该折已训练模型** + **预测日截面特征**算 SHAP，汇总 `mean(|SHAP|)` / 占比 / 平均符号方向，回答「输入特征里谁在推分」。
- **何时用**：训练完想看主导因子；与 `feature_importance_*.csv`、Clustered FI 对照解读。
- **默认**：关闭（避免拖慢全量 WF）。依赖 `shap`（已在 `requirements.txt`；Windows 用 venv 内 `pip install -r requirements.txt` 即可）。
- **支持模式**：`ridge` / `lgbm` / `xgb` / `cat` / `rf` / `ensemble`（及 multi-horizon 子训练）。`linear` / `dynamic` 无树/线性拟合器，开关无效。`mlp` 跳过。
- **防泄漏**：只用该折模型 + 对应预测截面；不做训练集自解释。
- **与现有重要性区别**：

| 产物 | 口径 | 典型问题 |
|------|------|----------|
| `feature_importance_*.csv` | 树分裂增益或 \|coef\| | 训练期「模型爱用谁」 |
| Clustered FI（`--report`） | 相关聚类 + MDA（IC 下降） | 共线时谁真贡献预测力 |
| **SHAP（`--shap`）** | 实例级边际贡献再聚合 | **预测时谁主导推分** |

特征中性化后，SHAP 特征名与白名单 / 注入因子名一致（残差化不改列名）。

```powershell
.\.venv\Scripts\python.exe run.py --skip-download --mode ensemble --horizon 5 `
  --factor-config config\factor_configs_h5_top31_pure_ic.yaml `
  --models lgbm,xgb `
  --shap --shap-top 20 `
  --output-dir results\ensemble_h5_shap
```

常用旋钮：`--shap-top N`（日志/JSON Top-N，默认 20）、`--shap-max-samples 500`（每折子采样）、`--shap-max-dates 12`（仅最近 N 个预测日；`<=0` = 全部）。

产物（在 `--output-dir` 或 `results/<tag>/`）：

| 文件 | 内容 |
|------|------|
| `shap_fold_<tag>.csv` | 折级长表（date/model/window/feature/mean_abs_shap/…） |
| `shap_by_model_<tag>.csv` | 按模型聚合 |
| `shap_summary_<tag>.csv` | ensemble 加权总表（因子、mean_\|SHAP\|、share、mean_shap） |
| `shap_summary_<tag>.json` | Top-N + meta（方法、采样参数） |

`--report` 仍会弹图（含 SHAP bar）；若未开 `--shap`，报告末尾会用**末折残留模型**补一份轻量 CSV（代表性弱于训练期 `--shap`）。

Ridge 说明：优先 `shap.LinearExplainer`；失败则 fallback `coef × 中心化特征`（写入 JSON `method`）。Ensemble：各子模型 Tree/Linear SHAP 后按窗口 IC 权重 × 模型动态权重聚合，**不用** Kernel 抽样最终 score。

## 7. 如何读结果

实验目录（`--output-dir` 或 `results/<tag>/`）内常见文件：

| 文件 | 看什么 |
|------|--------|
| `run.log` | 是否跑完、特征数、调仓频率、报错 |
| `model_metrics_<tag>.json` | 样本外（Out-of-Sample，OOS）IC 均值、ICIR、IC>0 胜率、预测期数 |
| `ic_series_<tag>.csv` | 逐期 IC 序列 |
| `factor_scores_<tag>.parquet` | 调仓日 × 股票得分 |
| `backtest_*_risk_metrics.csv` | 各 track 年化收益 / 波动 / **夏普（Sharpe）** / 索提诺（Sortino） / **最大回撤** / 信息比率（IR）等 |
| `backtest_*.png` | 净值曲线、多空、分位年化单调性 |
| `holdings_top*_*.csv` | （若 `--holdings`）每期持仓 |
| `feature_importance_<tag>.csv` | 训练期树增益 / \|coef\| |
| `shap_summary_<tag>.csv` / `.json` | （若 `--shap`）因子 SHAP 贡献汇总 |

### 7.1 建议阅读顺序

1. **`model_metrics`**：OOS IC / ICIR / 胜率是否稳定（判「有没有截面预测力」）。
2. **分位 Q1–Q5**：`pd.qcut` 升序，**Q1=最低分，Q5=最高分**；看年化是否大致单调、多空（Q5−Q1）符号是否与 IC>0 一致。
3. **Top-N vs 等权基准（benchmark）**：看「按得分取头部」相对全市场等权是否有超额；关注 **IR / 超额**，不要只盯绝对夏普。
4. **最大回撤与历年条形图**：是否某一年（如风格崩溃年）主导结论。

### 7.2 重要提醒：绝对夏普 ≠ 纯截面能力

- 多头满仓净值夏普里混有**市场 β**、调仓频率、成本与涨跌停执行摩擦。
- 开了 `--position-regime` 后，夏普更偏「选股 × 择时敞口」的**策略**指标。
- 评价「模型会不会排序」：优先 **IC / ICIR / Q 单调 / Top−等权超额（IR）**。
- 评价「能不能当交易策略」：再看扣成本后的 Top-N / 持仓规则夏普，并承认测的是「规则 × 模型」整体。

## 8. 常见坑

1. **重复进程抢同一目录**  
   两个 `run.py` 写同一 `--output-dir`，或 IC `--save` 与冒烟测试覆盖同一 `selected_factors_h*.json`，会导致半截结果或假 resume。一次一个重活；实验目录用日期后缀。

2. **不要用 Tee-Object / `>` 存日志**  
   看 `run.log`（UTF-8）。见 §1.2。

3. **先看 `run.log` 再下结论**  
   确认 `freq=`（`W-FRI` / `ME`）、特征中性化是否开启、是否误开 `two_stage` / `posreg`、预测期数是否合理。

4. **月频旧结果在修日历前不可比**  
   ME 调仓已改为「月末最后交易日」。修前 h20 的调仓点数 / OOS 起点可能偏少或偏晚；不要与修后数字混排对比。

5. **市值因子与 Barra 纯 IC**  
   纯化后市值类因子 IC 常接近 0。要用市值，走 `--special-factors size` 或独立假设，勿假装「过了纯 IC 门槛」。

6. **h5 / h20 IC 参数必须一致**  
   漏 `--use-fdr` 或关 `--corr-dedup` 会导致名单不可比；GS 现为可选（`--gram-schmidt`）。用 §3.2 命令，并核对 JSON 的 `config_snapshot`。

7. **改 IC 阈值后勿盲目 `--resume`**  
   可能沿用陈旧 selection / Gram-Schmidt checkpoint；改参请全量重跑或 `--fresh`。

8. **`clean_ret` 与涨跌停**  
   量价因子必须用清洗收益（涨跌停日为 NaN），不要自己 `prices.pct_change()` 另算一套。

9. **IC 产物覆盖**  
   `--save` 会归档旧文件到 `_archive/`，但冒烟 `--sample` 仍可能写出「很小」的新 `selected_factors_*.json`。全池结果跑完前不要让 driver / 训练去读半成品。

10. **并行与内存**  
    勿叠加 `driver --parallel-ic` 与高 `--workers`；32GB 保持 workers=1。
