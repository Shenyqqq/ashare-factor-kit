# 量化选股框架 · 操作手册

> **用途**：在无 AI 助手时，按本文独立完成环境配置、信息系数（IC）筛选、训练打分、分组回测、消融对照与 **Live 出候选股**。  
> **定位**：A 股多因子量化选股，**辅助人工二次筛选**，不做全自动交易。  
> **主入口**：仓库根目录 `run.py`；IC 筛选：`python -m research.ic_analysis_v2`；生产 live：`python -m live.predict_from_wf_models`。  
> **相关文档**：设计意图见 [PROJECT_FEATURES.md](PROJECT_FEATURES.md)；PIT 审计底稿见 [PIT_AUDIT.md](PIT_AUDIT.md)；开发约定见仓库根 [AGENTS.md](../AGENTS.md)。本文是用户操作的**唯一真源**。

## 2. 端到端主流程

数据流（与 `AGENTS.md` 一致）：

```text
AKShare → data/raw/*.parquet（含退市股）
  → 清洗 clean_ret + 涨跌停 masks（内存）
  → 时点对齐（Point-In-Time，简称 PIT：财务披露日 / 行业面板）
  → IC v2 筛选 → factor_configs YAML
  → Walk-Forward / Dynamic 训练 → factor_scores
  → backtest/quantile.py 分组回测 → results/<tag>/
```

|------|--------|----------|
| Step 0 | 数据已在本地则可跳过下载 | `python run.py --skip-download ...` |
| Step 1 | （可选）更新原始数据 | 去掉 `--skip-download`；日常增量见 §10.1；首次全量见下 |

| Step 4 | 训练打分 + 分组回测 | §4（研究基线 lgbm；旗舰 xgb 见文首） |

- **默认不要**加：`--position-regime`、非 `ew` 的 `--portfolio-opt`、`--two-stage`（见 §5）。

## 3. 标准 IC 筛选（canonical）

### 3.1 为什么叫 canonical？

持仓期 5（h5）与 20（h20）的生产白名单**必须用同一套 CLI 参数**，否则名单规模/构成不可比（历史上曾出现 h20 未开相关去重、因子数虚高）。相关去重（correlation dedup）**默认已开启**；关闭用 `--no-corr-dedup`（生产勿关）。

术语（首次出现）：

- **信息系数（Information Coefficient，IC）**：截面上因子值与前瞻收益的秩相关（或线性相关），衡量预测力。
- **IC 信息比率（ICIR）**：IC 均值 / IC 标准差，衡量稳定性。
- **Newey-West（NW）t**：对 IC 序列做异方差自相关稳健 t 检验。
- **Benjamini-Hochberg 错误发现率（BH-FDR）**：多重检验校正，控制假阳性。
- **Barra 纯 IC**（可选消融）：把因子对 **9 个 Barra 风格 + 行业** 做 **WLS**（权重=√市值）取残差后再算 IC。日常生产筛选默认改为 **sizeind**（只控 Size + PIT 行业），见 §3.2；`--barra` 与 `--neut-controls size*` **互斥**。
- **sizeind 纯 IC**（日常）：`--neut-controls size_industry`，残差化控制变量为 `log(流通市值)` + PIT 申万二级哑变量，回归仍是 WLS √市值。
- **多头/空头贡献（Q1 vs Q5）**：在同一套残差因子上，先按 pure IC 均值对齐方向（负则翻转），再按截面五分组看 Q5/Q1 相对截面的收益（见 §3.3a）。随中性化开启（sizeind 或 barra），不是「只有 --barra 才有」。
- **Gram-Schmidt 正交精筛**：在粗筛候选上逐个正交，保留残差仍显著的独立因子（写入 `factors_orth`）。
- **稠密硬门（pure AND）**：入池要求 `|IC_eff| > 0.015` **且** `|ICIR_eff| > 0.30`（合取 AND，勿改 OR）。开中性化时二者均来自 **pure IC 序列**（pure ICIR ≠ summary raw ICIR）；`--neut-controls raw` 或不中性化时退回 raw，仍为 AND。顺序：IC∧ICIR（∧t/FDR）→ **long_share**（默认 `>0.4`）→ corr-dedup →（可选 GS）。
- **long_share 门**：须用符号对齐后的分位分解列（`quantile_decomp`；分组前按 pure IC 均值翻转）。summary 已有则用；历史未对齐产物请按**同一套** `--neut-controls` 重跑，或 `--long-share-csv .tmp/quantile_ls_h5_aligned.csv` 离线合并。`--min-long-share 0` 关闭。
- **衰减因子（标注）**：同持仓期 IC 序列上 `R = |ICIR_recent| / |ICIR_past|`；衰减 iff `(R < 0.50 ∧ |ICIR_recent| < 0.20) ∧ |IC_recent| < 0.010`（**合取 AND**，勿改 OR）。默认近窗 `--decay-recent-months 6`（h5≈26 期）；**仅对稠密/稀疏/新兴入选或观察名单打标**（非全库）。开中性化时近窗用 pure IC 序列。**不剔除**，仍可在 `factors` 内警示（实盘谨慎）。
- **风格逆转（标注）**：最近一季内 `mean 1{sign(IC_t)≠sign(mean_IC) ∧ |IC_t|>0.015} > 0.75` → 标「风格逆转」。可与衰减叠加；**不剔除**（实盘近季反向警示；窗口仍为 `--reversal-months` 默认 3）。
- **新兴因子（emerging）**：全样本未过 `|IC|∧|ICIR|` 稠密门，且**最近约半年**（默认 `--emerging-lookback 6` 日历月 → h5≈26 期 / h20≈6 期）**pure** 近窗同时满足：① 近窗 NW-t 经 BH-FDR 显著（校正域=稠密轨**全体被测因子**）；② `|ICIR_recent|≥--emerging-recent-icir`（默认 0.35）；③ lift≥`--emerging-lift-min`（默认 1.5）；④ 默认再要求近 **3 个季度** `|ICIR|` 单调不降且末段>首段（`--emerging-trend`，可用 `--no-emerging-trend` 关）。**默认仅标注观察**（`factors_emerging`），**不**并入主池。禁止 raw 近窗救援；仍做 corr-dedup。开中性化时近窗对齐 pure 序列。
- **新兴 holdout / 偷看**：全样本定池本就有选择偏差；**用评效段（如 2026）定池会双重偷看**。近窗统计可截到 `--emerging-asof 2025-12-31`，或 `--emerging-holdout-months 6`（默认 0=现状）。「三季度增强」减轻但不能消灭偷看；评 2026 时**优先 holdout/asof**。
- **稀疏因子（sparse）**：截面大量无信号（龙虎榜 / 涨跌停 / 开板 / 解禁 / 高管 / 大宗 / 业绩预告等），走独立筛选轨道，不进 dynamic；**无 t/NW-t/FDR**。胜率/触发侧按全样本 `s=sign(mean_IC)` 对齐（负 IC 因子不按盲目 `IC>0` / `f>0`）。胜率/payoff 过线后做 **corr-dedup**（默认阈值 0.70，见下）。
- **触发日截面胜率（payoff_hit）**：稀疏轨主门槛之一。触发侧 `f*s>0`（`s<0` 时为 `f<0`），`mean_t 1{ mean(y|f*s>0) > mean(y) }`；日期与普通 IC / 胜率相同（`ic_series` 全部有效交易日，**非**调仓日子集）；默认 ≥ 0.55。`mean_IC≈0` 时跳过稀疏门。

### 3.2 完整命令（h5 / h20 只改 `--period`）

在仓库根目录、一次只跑一个 period（全池约数小时级，视机器而定）：

```powershell
# h5（持仓约 5 交易日 / 周频标签）—— 日常：sizeind 纯 IC
.\.venv\Scripts\python.exe -m research.ic_analysis_v2 --period 5 `
  --neut-controls size_industry --save --use-fdr --t-threshold 2.5 --decay

# h20（持仓约 20 交易日 / 月频标签）——同参，只改 period
.\.venv\Scripts\python.exe -m research.ic_analysis_v2 --period 20 `
  --neut-controls size_industry --save --use-fdr --t-threshold 2.5 --decay
# 需要 factors_orth（dynamic）时再加 --gram-schmidt
```

| 旋钮 | 生产约定 | 含义 |
|------|----------|------|
| `--neut-controls size_industry` | **日常显式打开** | Size + PIT 行业纯 IC（与旗舰 ML 特征中性化同口径） |
| `--barra` | **可选消融** | 9 风格 + 行业纯 IC；与 `--neut-controls size*` **互斥** |
| `--quantile-decomp` | **默认 ON**（随中性化） | Q1/Q5 多头空头贡献；`--no-quantile-decomp` 关闭 |
| `--quantile-y-mode` | `residual` | 分位收益口径：`residual`（y 再残差化）/ `raw`（pure IC 同款 y） |
| `--save` | 显式打开 | 写入 `research/output/` |
| `--use-fdr` | **默认 ON** | BH-FDR 多重检验（**仅稠密轨**） |
| `--t-threshold 2.5` | 2.5 | NW_t / FDR 配套阈值（**仅稠密轨**） |
| `--gram-schmidt` | **默认 OFF** | 正交精筛 → `factors_orth`（显式 `--gram-schmidt` 开启） |
| `--corr-dedup` | **默认 ON** | 截面相关去重；`--no-corr-dedup` 关闭 |
| `--min-long-share` | **默认 0.4** | 符号对齐后 `long_share >` 阈值；`--min-long-share 0` 关闭 |
| `--long-share-csv` | 可选 | 合并/覆盖对齐后 long_share（未重跑中性化 IC 时用） |
| `--decay` | 可选 | 算跨持仓期衰减表（诊断）；**不再**作筛选主门 |
| `--decay-gate` | **默认 ON** | 同持仓期衰减**标注**（合取）；`--no-decay-gate` 关闭 |
| `--reversal-label` | **默认 ON** | 风格逆转**标注**；`--no-reversal-label` 关闭 |
| `--emerging` | **默认 ON** | 新兴因子**观察标注**（不进主池）；`--no-emerging` 关闭 |
| `--sparse-track` | **默认 ON** | 稀疏独立轨道；`--no-sparse-track` 关闭 |
| `--corr` | 默认关 | **仅打印**相关矩阵，不控制去重 |
| `--fresh` | 按需 | 清空本 period 的 checkpoint 后全量重算 |
| `--resume` | 按需 | 从 checkpoint 续跑；**改阈值 / 改 neut-controls 后不要 resume** |
| `--only-new` | 按需 | **增量 IC**：只算 registry 相对 `ic_series` 缺失的因子；`barra_pure` 指纹匹配时只补新区并 merge；仍重跑 summary/selection |
| `--factors` | 按需 | 只算逗号分隔的因子名并 merge；同上，不清全量 `barra_pure`（指纹失效除外） |

### 3.3a 多头/空头贡献（pure 路径）

**目的**：判断纯 IC 主要来自「多头（Q5）强」还是「空头（Q1）弱」。分解在「越高越好」方向上做。日常控制矩阵是 sizeind；可选消融才用完整 Barra 9 风格。

**口径**（与 pure IC 同日、同控制矩阵；回归为 **WLS，权重=√市值**，不是 OLS）：

1. 每个调仓日，对因子做 WLS：`resid_x = f - [1, 控制变量] β`（sizeind = Size + 行业；`--barra` = 9 风格 + 行业；与 pure IC 的 x 相同）。
2. 收益侧默认再残差化：`resid_y = y - [1, Barra, 行业] γ`（`--quantile-y-mode residual`）；也可选 `raw` 直接用 pure IC 的 forward return。
3. **IC 方向对齐**：若该因子时序 pure IC 均值 < 0，对用于分组的 `resid_x` 取反（pure IC 序列本身不取反），使「高分 = 预测收益更高的一侧」。
4. 对对齐后的 `resid_x` 做五分位（`qcut` on rank，ties 用 first；bins 不足则跳过该日），算各组等权 `resid_y`（或 raw y）。Q5=名义多头，Q1=名义空头。
5. 单日：`多头超额 = Q5 - CS_mean`，`空头贡献 = CS_mean - Q1`，`spread = Q5 - Q1`，`long_share = 多头超额 / (多头超额+空头贡献)`（分母>0）。
6. 时序平均后：`long_share > 0.65` → **多头主导**；`< 0.35` → **空头主导**；其间 → **双边**；对齐后合计超额仍≤0（数值病态）→ **无效**。**不要**因负 IC 未翻转而标无效。

**注意**：仓库里 pure IC 本身是 `Spearman(resid_x, y_raw)`（残差化的是因子，不是收益）。分位分解默认对 y 再残差化，是为了用风格/行业中性收益解释多空来源；若要与 pure IC 的 y 完全一致，用 `--quantile-y-mode raw`。列名未变，但负 IC 因子的 Q5/long_share/多空来源按对齐后口径；需按同一套 `--neut-controls` 重跑 IC 才会更新已落盘 CSV。

**解读**：

| 多空来源 | 含义 | 实盘提示 |
|----------|------|----------|
| 多头主导 | 对齐后高分组相对截面赚得多 | 更适合做多/选股增强 |
| 空头主导 | 对齐后低分组相对截面亏得多 | IC 多来自「避开差票」；做多组合可能偏弱 |
| 双边 | 两侧都有贡献 | 多空对冲叙事更完整 |
| 无效 | 对齐后多空合计仍无正超额 | 勿解读方向（非「负 IC」同义） |

开关：`config/settings.py` 中 `IC_QUANTILE_DECOMP` / `IC_QUANTILE_Y_MODE` / `IC_QUANTILE_BILATERAL_LO|HI`；CLI `--quantile-decomp` / `--no-quantile-decomp` / `--quantile-y-mode`。

**新兴 corr-dedup 方案**：候选按近窗 \|ICIR\| 降序；与已保留稠密因子及已选新兴做 IC 序列相关去重（优先 pure 序列）；仅影响 `factors_emerging`，不改主池。

**稀疏 corr-dedup 方案**（胜率/payoff 过线后、写入 `factors_sparse` 前）：
1. 优先与稠密一致：截面 Spearman + `--corr-method`（默认 `max`）聚合（复用 `_pairwise_corr_matrix` / `_aggregate_corr`）；
2. 若截面矩阵为空或不稳定（稀疏触发日重叠不足 `min_periods`，硬套截面会静默跳过去重）→ **fallback** IC 序列 Pearson 相关（与 emerging / `--raw-select` 同口径）；
3. 候选按 \|ICIR\| 降序；`|corr| > --sparse-corr-threshold`（默认 0.70）时剔除较弱者，理由写入 `excluded`；
4. 受 `--corr-dedup` / `--no-corr-dedup` 统一开关控制；仅影响 `factors_sparse`，不改稠密主池。

#### 入选类别定义

| 类别 | 含义 |
|------|------|
| 普通因子 | 稠密池全样本过线（IC/ICIR/t/FDR/corr）→ `factors` |
| 稀疏因子 | 语义稀疏池：同向 IC 胜率 + 触发日截面胜率过线（按 `sign(mean_IC)`；无 t/FDR）→ 再 corr-dedup |
| 新兴因子 | 全样本未过 IC/ICIR 门 + 近窗 FDR∧ICIR∧lift；**仅观察**，不进主池 |
| 衰减因子 | 警示标签：R 塌缩 ∧ 近期 ICIR 弱 ∧ 近期 \|IC\| 弱；**仍可在 factors 池** |
| 风格逆转 | 警示标签：近一季多数强 IC 与全样本符号相反；可与衰减叠加 |

### 4.2 `--horizon` 与调仓频率

实现：`utils/rebalance_dates.py::horizon_to_rebalance_freq` + `get_rebalance_dates`。

| `--horizon` | 含义（标签） | 映射的调仓频率 | 实际调仓日 |
|-------------|--------------|----------------|------------|
| 3 | 超短（研究用） | `3D` | 桶内最后交易日 |
| **5** | 约一周持有 | **`W-FRI`（周频）** | 该周最后一个有行情的交易日 |
| 10 | 约双周 | `2W-FRI` | 同上 |
| **20** | 约一月持有（标签） | **`ME`（自然月）** | **该月最后一个交易日**（已修日历 bug） |
| 60 | 约一季 | `ME` 同类月频映射 | 月末最后交易日 |

要点：

1. **h5 ≠「每 5 个自然日」**，而是「约 5 日前瞻收益标签 + **周频**调仓」。
2. **h20 ≠「每 20 个交易日调仓」**，而是「约 20 日标签 + **真·月末**调仓」。一个月交易日常约 20～22，只是近似。
3. 调仓日取 **`groupby`/`resample` 桶内最后一个真实交易日**，不再把周末/假日当调仓日（历史「ME bug」：用日历月末虚拟日导致整月错位/点数偏少）。**修日历之前的月频（h20）回测结果不可与修后结果直接对比。**

### 4.4 默认实验姿态（请遵守）

做「模型 / 因子」消融时，**默认不要**加：

- `--position-regime`（仓位体制）
- `--portfolio-opt` 非 `ew`（组合优化；默认已是等权 `ew`）
- `--two-stage`（两段式 ridge）

这些是**组合层 / 结构层**旋钮，会改变「绝对夏普」叙事；与「截面排序能力」对照时先保持关闭，见 §5、§7。日常对照请显式 `--neut-controls size_industry`，不要依赖代码默认的 `barra`。

### 4.5 Walk-Forward：双窗 vs 单窗

实现：`models/trainer.py`（`TRAIN_WINDOWS_MONTHS = [6, 12]`，`VAL_WINDOW_MONTHS = 6`）+ purged split / embargo（AFML Ch.7）。

**双窗 WF（代码默认，手册仍保留怎么用）**

- `--train-windows 6,12`（单位默认日历月）+ `--val-window 6`：两窗**共用**预测日前的近期 val `[idx-V, idx)`，各自 train `[idx-V-W, idx-V)`。
- 多窗集成默认 `--wf-selection ic_weighted`（IC 加权 Z-score，不是盲 rank 平均）。
- `val_window=0` 且仍多窗时，须 `--wf-selection average`（无独立 val 不能按 val IC 加权）。

**单窗 + val=0（日常研究与旗舰）**

- 无独立 val：train 贴预测日 `[idx-W, idx)`，仍 purge / embargo。
- 周频 W-FRI：**104 期 ≈ 2 年**（手册演变里的「2 年窗」）；**156 期 ≈ 3 年**（**当前旗舰**，yaml `train_windows: [156]`）。
- 旗舰：`--train-windows 156 --train-window-units periods --val-window 0 --retrain-every 4`。
- `retrain_every=4`：fit 日 = 调仓序号 ≡ 0 (mod 4)；中间 3 期复用上一 fit 模型（live 必须按同一调度加载，见 §10）。

不要把「2 年」写成 156 期，也不要把旗舰改写成 lgbm。

### 4.6 训练标签：cs_rank（不 winsor）

- `--label-mode` 代码与手册默认都是 **`cs_rank`**：每个调仓日对 raw `forward_return` 做截面百分位，**跳过** 1%/99% winsor（日志可见 `cs_rank: skip fwd_return_winsor`）。
- `--fwd-return-winsor` 默认开，但 **cs_rank 路径仍跳过**；只有 `--cs-rank-winsor` 才「先截尾再 rank」（消融）。
- 其它模式（`cs_zscore` / `raw` / `barra_residual` 等）仍按 `--fwd-return-winsor` 截尾。
- `--objective regression`（默认）+ `cs_rank` 标签 ≠ `--objective rank`（Learning-to-Rank 损失）。旗舰是前者。

### 4.7 训练池 / 预测池 / 回测得分宇宙（必须对齐理解）

三层语义不要合成「可交易收益」一条：

| 层 | 默认 | 做什么 |
|----|------|--------|
| **因子 `clean_ret`** | 涨跌停日收益=NaN | 量价因子不把涨跌停当普通收益 |
| **IC / ML 训练可交易池** | **research**：信号日**保留**涨跌停；仍剔 ST / 停牌 / 零成交 / 次新 / 退市 | `TRADABLE_EXCLUDE_LIMIT_SIGNAL_DAY=False`；标签默认 **不做** execution mask（`FWD_RETURN_EXEC_MASK=False`） |
| **回测成交** | 买日一字涨停买不进、卖日涨跌停卖不出 | 与研究池无关 |
| **回测得分宇宙** | **`--bt-score-universe strict`** | 落盘分数可保留训练覆盖；回测前 `mask_scores_for_backtest` 裁到「严格可交易 ∩ label-exec 门控可用」，避免训练池更大把等权基准/Q 组抬歪 |
| **Live 出分** | 生产路径与回测 **strict** 同口径 | `live.predict_from_wf_models`；旗舰 yaml 写 `tradable: research`（训练）+ `bt_score_universe: strict`（出分/回测） |

恢复旧「信号日也剔涨跌停、标签也做 exec mask」：`--tradable-strict` / `--label-exec-mask` 或 `--tradable-limit-mode strict`。诊断才用 `--bt-score-universe train`（与训练池一致）。IC checkpoint 后缀 `_tmr_v2`；换口径须 `--fresh`。

研究能打分 ≠ 回测一定能成交 ≠ live Top-N 一定可买。旗舰还剔 B 股（200/900）、保留北交所 92。

## 5. 可选功能（默认关闭）

### 5.1 仓位体制 `--position-regime`

- **做什么**：用市场趋势 / 波动 / 广度合成 `target_exposure ∈ [e_min, 1]`（默认 `e_min=0.30`），在分组回测里缩放**非基准** track 的收益（现金收益记 0）。解决「买多少」，不解决「买谁」。
- **信号（PIT，全部 `shift(1)`）**：中证全指 `close/MA60−1`（趋势）、`σ_20 / median_252(σ_20)`（波动）、个股站上 MA20 占比（广度）；`size_style`（小盘−大盘）仅记录、默认不进敞口合成。实现：`backtest/regime.py`。
- **何时用**：验证「中等选股 + 降仓避险」的**策略**夏普；不要当作截面 alpha 的证明。
- **默认**：关闭时与旧实验路径 bit-identical。

```powershell
.\.venv\Scripts\python.exe run.py --skip-download --mode lgbm --horizon 5 `
  --factor-config config\factor_configs_h5_sizeind_20260815.yaml `
  --neut-controls size_industry --position-regime `
  --output-dir results\lgbm_h5_posreg

# 强制半仓（覆盖规则合成）
# ... --position-regime --force-exposure 0.5
```

别名：`--pos-regime`。产物含 `position_exposure_*.csv` / `position_regime_*.csv`；tag 后缀 `_posreg`。  
已退役：`--regime-cs`、`--no-regime`、`--ridge-drop-regime`（现为 no-op，可省略）。可与 `--portfolio-opt` 叠加：先优化 invested book（权和=1），再按敞口缩放；不要把 `target_exposure` 再折进权重和。

### 5.2 组合优化 `--portfolio-opt`

- **做什么**：在**已选**股票集合（Q 分位 / Top-N）上分配权重；**不负责选股**。
- **默认**：`ew`（等权），与历史路径一致。
- **何时用**：对照得分加权 / 逆波动等；小资金优先 `ew` / `rank` / `invvol`。`mv` / `rp` 仅作消融（周频小 N 上 Σ 嘈杂；非 Barra QP）。
- **方法**：`ew` 等权；`score` 得分正比；`rank` 截面 rank 正比；`invvol` 逆波动；`mv` 均值-方差 lite；`rp` 简易风险平价（失败回退 invvol）。实现：`backtest/optimize.py`。

```powershell
.\.venv\Scripts\python.exe run.py --skip-download --mode lgbm --horizon 5 `
  --factor-config config\factor_configs_h5_sizeind_20260815.yaml `
  --neut-controls size_industry `
  --portfolio-opt invvol --max-weight 0.1 --top-n 30 `
  --output-dir results\lgbm_h5_invvol
```

可选值：`ew` | `score` | `rank` | `mv` | `invvol` | `rp`。非 `ew` 时 tag 后缀 `_opt{method}`。可与 `--position-regime` 叠加：先优化 invested book（权和=1），再按敞口缩放收益。`benchmark` track 始终等权。

### 5.3 两段式 `--two-stage`

- **做什么**：阶段 1（S1）全市场 Walk-Forward 打分 → 每期取 S1 截面 top 分位池（默认 `--stage2-pool-frac 0.2` = **Top20%**）→ 阶段 2（S2）仅用历史「曾在池内」样本；**每个历史日在当日 S1 池内**对 label 与特征做 `winsor(1%/99%) → cs_zscore`，再拼接拟合 Ridge MSE；推理日对当日池内特征做同样变换后预测 → **有分日池外写回 `-inf`**（避免 `qcut`/基准宇宙缩成池内；未拟合暖机日仍为全 NaN）。实现：`models/wf/two_stage.py`。
- **与单段 Q5 对照**：全市场五分位下 Top20% ≈ **Q5**，故二段**池内等权基准**在同一可交易宇宙与成本口径下，理论上应接近单段 **Q5**——用来验 bug / 对照，不是业绩承诺。
- **口径**：样本仍为 S1 TopK%；标签与特征均为**池内**截面变换（不是全市场 raw / 不是多日混做一次 zscore）。若开了 `--feature-neutralize`，顺序为：全局残差化（日常 sizeind）→ S2 再在池内 winsor→zscore。
- **一级 cache（universe only）**：完整 `--two-stage`（或显式 `--save-stage1-cache`）会写出 `results/<tag>/stage1_cache/`：
  - **存**：`s1_scores.parquet`、`s1_pool_mask.parquet`、`meta.json`（horizon、factor-config 路径/哈希、sparse、feature_neutralize、pool_frac、调仓日、产出时间等）
  - **不存**：池内特征 X、标签 y（二级换因子池/loss 时用 cache 的股票×日期 universe，按当前 YAML 现算并在池内 winsor→zscore）
  - 换一级模型或一级 YAML **必须换 cache**（看 `meta.factor_config_hash` / tag）。
- **何时用**：对照「头部再精排」是否改善 Top-N；**不是**默认生产路径。
- **警告（h5 实测）**：同因子 + event 下，旧口径两段式相对单段 ridge **明显更弱**（例：样本外 ICIR 从约 0.84 降到约 0.04；Top100 夏普约 0.75 → 0.41）。新池内 zscore / Top20% 口径需重新对照；在未验证前**不要默认开启**。
- 不加 `--two-stage` 时**不会**进入两段路径，不影响普通回测。

```powershell
# 完整二段（默认 pool=0.2，并写出 stage1_cache）
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_sizeind_20260815.yaml `
  --special-factors event --feature-neutralize --neut-controls size_industry `
  --two-stage --stage2-pool-frac 0.2 --top-n 100 `
  --output-dir results\ridge_h5_twostage

# 只跑一级并强制落 cache（供后续换二级因子）
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_sizeind_20260815.yaml `
  --feature-neutralize --neut-controls size_industry --save-stage1-cache `
  --output-dir results\ridge_h5_s1_only

# 从 cache 跳过 S1，用「当前」factor-config 现算二级特征跑 S2
.\.venv\Scripts\python.exe run.py --skip-download --mode ridge --horizon 5 `
  --factor-config config\factor_configs_h5_stage2.yaml `
  --feature-neutralize --neut-controls size_industry `
  --two-stage --stage1-cache results\ridge_h5_twostage\stage1_cache `
  --top-n 100 --output-dir results\ridge_h5_s2_from_cache
```

### 5.4 特殊因子 `--special-factors`

- **做什么**：在 YAML 白名单过滤**之后**，把不必经 IC 白名单的因子 pack **强制注入**训练/打分（IC 筛选路径不变）。
- **默认**：注入因子 `skip_neutralize=True`（开特征中性化时豁免残差化，无论 sizeind 还是 Barra）。
- **`--mode dynamic` 禁止注入**：会 warning 并忽略；`blend-dynamic` 的 dynamic 半边同样拒绝。稀疏/事件包只给 ridge / 树等 ML 路径。
- 实现：`factors/special_factors.py`、`factors/sparse_factors.py`。

| Pack | 内容 | 说明 |
|------|------|------|
| `event` | 如 `业绩预告_超预期` | 事件层；旧 `--event-overlay` 已弃用但仍可用 |
| `size` | `对数市值` / `市值分位` / `市值风格对齐_*` | 市值 alpha；也可写进 YAML，inject 是为了不依赖过线 |
| `sparse` | 龙虎榜/涨跌停/开板/解禁/高管/大宗/业绩预告等 | IC `factors_sparse`；注入时**方差对齐**（供 ridge L2） |

**方差对齐（variance alignment）**：稀疏列堆叠后方差常 ≪ 1，Ridge 的 L2 会压死系数。注入时缩放  
`x' = x * (target_std / std(x_finite))`，默认 `target_std=1.0`（与截面 z-score 后稠密因子同量级）。树模型无需额外处理。

```powershell
# 事件
--special-factors event

# 市值
--special-factors size

# 稀疏（全量语义池；生产更推荐从 IC JSON 取入选名）
--special-factors sparse
--sparse-from-ic research\output\selected_factors_h5_sizeind_20260815.json

# 组合；或写具体因子名
--special-factors event,size,sparse
--special-factors 对数市值,市值分位
```

别名：`--inject-factors`。tag 后缀如 `_event`、`_size`、`_sparse`。

**市值 vs 纯 IC**：在 sizeind / Barra 纯化后，`对数市值` / `市值分位` 等纯 IC 常接近 0（风格已被控掉）。若仍要用市值信号，用 `--special-factors size` 并接受「非纯 alpha」叙事，或做独立消融，勿与「纯 IC 过线名单」混为一谈。

### 5.5 SHAP 因子贡献 `--shap`

- **做什么**：在 Walk-Forward **最近若干预测日**上，用**该折已训练模型** + **预测日截面特征**算 SHAP，汇总 `mean(|SHAP|)` / 占比 / 平均符号方向，回答「输入特征里谁在推分」。
- **何时用**：训练完想看主导因子；与 `feature_importance_*.csv`、Clustered FI 对照解读。
- **默认**：关闭（避免拖慢全量 WF）。依赖 `shap`（已在 `requirements.txt`；Windows 用 venv 内 `pip install -r requirements.txt` 即可）。
- **支持模式**：`ridge` / `lgbm` / `xgb` / `cat` / `rf` / `ensemble`（及 multi-horizon 子训练）。`linear` / `dynamic` 无树/线性拟合器，开关无效。`mlp` 跳过。
- **防泄漏**：只用该折模型 + 对应预测截面；不做训练集自解释。
- **与现有重要性区别**：

| 产物 | 口径 | 典型问题 |
|------|------|----------|
| `feature_importance_*.csv` | 树分裂增益或 \|coef\| | 训练期「模型爱用谁」 |
| Clustered FI（`--report`） | 相关聚类 + MDA（IC 下降） | 共线时谁真贡献预测力 |
| **SHAP（`--shap`）** | 实例级边际贡献再聚合 | **预测时谁主导推分** |

特征中性化后，SHAP 特征名与白名单 / 注入因子名一致（残差化不改列名）。

```powershell
.\.venv\Scripts\python.exe run.py --skip-download --mode ensemble --horizon 5 `
  --factor-config config\factor_configs_h5_sizeind_20260815.yaml `
  --models lgbm,xgb --neut-controls size_industry `
  --shap --shap-top 20 `
  --output-dir results\ensemble_h5_shap
```

常用旋钮：`--shap-top N`（日志/JSON Top-N，默认 20）、`--shap-max-samples 500`（每折子采样）、`--shap-max-dates 12`（仅最近 N 个预测日；`<=0` = 全部）。

产物（在 `--output-dir` 或 `results/<tag>/`）：

| 文件 | 内容 |
|------|------|
| `shap_fold_<tag>.csv` | 折级长表（date/model/window/feature/mean_abs_shap/…） |
| `shap_by_model_<tag>.csv` | 按模型聚合 |
| `shap_summary_<tag>.csv` | ensemble 加权总表（因子、mean_\|SHAP\|、share、mean_shap） |
| `shap_summary_<tag>.json` | Top-N + meta（方法、采样参数） |

`--report` 仍会弹图（含 SHAP bar）；若未开 `--shap`，报告末尾会用**末折残留模型**补一份轻量 CSV（代表性弱于训练期 `--shap`）。

Ridge 说明：优先 `shap.LinearExplainer`；失败则 fallback `coef × 中心化特征`（写入 JSON `method`）。Ensemble：各子模型 Tree/Linear SHAP 后按窗口 IC 权重 × 模型动态权重聚合，**不用** Kernel 抽样最终 score。

## 7. 如何读结果

实验目录（`--output-dir` 或 `results/<tag>/`）内常见文件：

| 文件 | 看什么 |
|------|--------|
| `run.log` | 是否跑完、特征数、调仓频率、报错 |
| `model_metrics_<tag>.json` | 样本外（Out-of-Sample，OOS）IC 均值、ICIR、IC>0 胜率、预测期数 |
| `ic_series_<tag>.csv` | 逐期 IC 序列 |
| `factor_scores_<tag>.parquet` | 调仓日 × 股票得分 |
| `backtest_*_risk_metrics.csv` | 各 track 年化收益 / 波动 / **夏普（Sharpe）** / 索提诺（Sortino） / **最大回撤** / 信息比率（IR）等 |
| `backtest_*.png` | 净值曲线、多空、分位年化单调性 |
| `holdings_top*_*.csv` | （若 `--holdings`）每期持仓 |
| `feature_importance_<tag>.csv` | 训练期树增益 / \|coef\| |
| `shap_summary_<tag>.csv` / `.json` | （若 `--shap`）因子 SHAP 贡献汇总 |

### 7.1 建议阅读顺序

1. **`model_metrics`**：OOS IC / ICIR / 胜率是否稳定（判「有没有截面预测力」）。
2. **分位 Q1–Q5**：`pd.qcut` 升序，**Q1=最低分，Q5=最高分**；看年化是否大致单调、多空（Q5−Q1）符号是否与 IC>0 一致。
3. **Top-N vs 等权基准（benchmark）**：看「按得分取头部」相对全市场等权是否有超额；关注 **IR / 超额**，不要只盯绝对夏普。
4. **最大回撤与历年条形图**：是否某一年（如风格崩溃年）主导结论。

### 7.2 重要提醒：绝对夏普 ≠ 纯截面能力

- 多头满仓净值夏普里混有**市场 β**、调仓频率、成本与涨跌停执行摩擦。
- 开了 `--position-regime` 后，夏普更偏「选股 × 择时敞口」的**策略**指标。
- 评价「模型会不会排序」：优先 **IC / ICIR / Q 单调 / Top−等权超额（IR）**。
- 评价「能不能当交易策略」：再看扣成本后的 Top-N / 持仓规则夏普，并承认测的是「规则 × 模型」整体。

## 8. 常见坑

1. **重复进程抢同一目录**  
   两个 `run.py` 写同一 `--output-dir`，或 IC `--save` 与冒烟测试覆盖同一 `selected_factors_h*.json`，会导致半截结果或假 resume。一次一个重活；实验目录用日期后缀。`--save` 会把旧 CSV/JSON 归档到 `research/output/_archive/`，但冒烟仍可能写出很小的新文件。

2. **不要用 Tee-Object / `>` 存日志**  
   看 `run.log`（UTF-8）。见 §1.2。

3. **先看 `run.log` 再下结论**  
   确认 `freq=`（`W-FRI` / `ME`）、`--neut-controls` 是 size_industry 还是 barra、是否误开 `two_stage` / `posreg`、预测期数是否合理。漏写 `--neut-controls` 时 ML 会走代码默认 **barra**。

4. **月频旧结果在修日历前不可比**  
   ME 调仓已改为「月末最后交易日」。修前 h20 的调仓点数 / OOS 起点可能偏少或偏晚；不要与修后数字混排对比。

5. **市值因子与纯 IC**  
   sizeind / Barra 纯化后市值类因子 IC 常接近 0。要用市值，走 `--special-factors size` 或独立假设，勿假装「过了纯 IC 门槛」。

6. **h5 / h20 IC 参数必须一致**  
   漏 `--use-fdr` 或关 `--corr-dedup` 会导致名单不可比；GS 现为可选（`--gram-schmidt`）。日常用 §3.2 的 `--neut-controls size_industry`，并核对 JSON 的 `config_snapshot`。sizeind 与 `--barra` 产物不可混比。

7. **改 IC 阈值 / 中性化口径后勿盲目 `--resume`**  
   可能沿用陈旧 selection / Gram-Schmidt / `barra_pure` checkpoint；改参请全量重跑或 `--fresh`。

8. **`clean_ret` 与涨跌停**  
   量价因子必须用清洗收益（涨跌停日为 NaN），不要自己 `prices.pct_change()` 另算一套。训练池 research ≠ 回测 strict 得分宇宙，见 §4.7。

9. **IC 产物覆盖**  
   `--save` 会归档旧文件到 `_archive/`，但冒烟 `--sample` 仍可能写出「很小」的新 `selected_factors_*.json`。全池结果跑完前不要让 driver / 训练去读半成品。

10. **并行与内存**  
    勿叠加 `driver --parallel-ic` 与高 `--workers`；32GB 保持 workers=1。

11. **Live 口径**  
    不要把 `flagship_last_window` / `live.daily_update` 的 Top-N 拿去核对全 WF 回测净值。不要 `--force-refresh` 全量扫股本，不要给 `compute_market_cap` / `download_stock_value_em` 传「最近 N 天」当 `--start`。见 §10。

12. **旗舰 ≠ CLI 默认 ≠ 2 年窗记忆**  
    旗舰是 xgb / 156 期；研究基线是 lgbm / 104 期；`run.py` 默认 mode=linear、horizon=20、双窗 6+12 月、neut=barra。

## 10. Live：增量数据与按 fold 出候选股

定位：默认周五（W-FRI）**收盘后出信号**，**下一交易日开盘买**；人工看 Top100 / Top30；A 股 T+1。框架**不自动下单**。数据末日 = 信号日 T。

旗舰：`xgb_h5_sizeind_w156_nob`（`config/flagship_xgb_h5_sizeind_w156_nob.yaml`）。本节吸收原 live 运维要点，避免第二套真源。

### 10.1 增量更新数据（按顺序；日常不带 `--start`）

```powershell
cd F:\PythonProject\quant_trading
.\.venv\Scripts\activate
$env:TRAIN_MAX_WORKERS="1"; $env:IC_MAX_WORKERS="1"; $env:DYNAMIC_MAX_WORKERS="1"

python -m data.download
python -m data.download_stock_value_em     # 不要 --start；92 缺失可 --bj-only
python -m data.download_st_history         # 沪市新戴帽靠这一步；日更默认不会自动刷
python -m data.compute_market_cap          # 不要 --start，否则换手会被截断
python -m data.download_shares             # 按 refresh_stale_days 增量；不要 --force-refresh
```

东财行情挂了再考虑 `python -m data.backfill_prices_raw_sina`（不复权、逐只慢，只补缺口）。龙虎榜 / 解禁 / 大宗非旗舰每日必需。

**覆盖率（上线前至少看）：**

```powershell
python -c "import pandas as pd; d=pd.read_parquet('data/raw/close_hfq.parquet'); print('close_hfq', d.shape, d.index.max().date(), '末日非空', int(d.iloc[-1].notna().sum()))"
python -c "import pandas as pd; d=pd.read_parquet('data/raw/circ_mv.parquet'); print('circ_mv', d.shape, d.index.max().date(), '末日非空', int(d.iloc[-1].notna().sum()))"

```

数量级（随下载时点变，只作「塌了没有」的尺子）：`close_hfq` 末日非空应数千（曾见 ~5192）；`circ_mv` 末日非空应 ~5500+（曾见 ~5551）。**塌成几百只**说明东财增量没跑完就被 assemble 成稀疏行，须跑完再拼，不要对半成品 `--assemble-only`。`turnover` 若只剩几十行，多半是 `compute_market_cap` 带了最近日期的 `--start`。

### 10.2 生产主路径：全 WF `--save-models` + 按 fold 加载

与回测**同口径**（同一套 neut / Barra 缓存、同一批 fold 模型）。口径不变时全 WF 只需跑一次；换中性化 / horizon / 调仓频率须重跑。

```powershell
python run.py --skip-download --mode xgb --horizon 5 `
  --factor-config config\factor_configs_h5_sizeind_20260815.yaml `
  --special-factors sparse `
  --sparse-from-ic research\output\selected_factors_h5_sizeind_20260815.json `
  --train-windows 156 --train-window-units periods --val-window 0 `
  --retrain-every 4 --time-decay 0 --feature-neutralize --neut-controls size_industry `
  --bid-ask-spread 10 --save-models `
  --output-dir results\xgb_h5_sizeind_w156_nob_wf_<日期>
```

`--save-models` 把每个 fit 日写成 `results/<tag>/models/xgb_w156_<fitdate>.joblib`，并写 `models_manifest.json`（path / model / window / date / feature_names / feature_neutralize / neut_controls）。`training_diagnostics_*.csv` 每行有 `date / reused_model / fit_date`。

**fold 调度（`retrain_every=4`，W-FRI）**：fit 日 = pred_offset ≡ 0 (mod 4)；中间 3 期复用上一 fit。例：信号日 2026-08-28 的 pred_offset=18 → 复用 2026-08-14 模型（08-21、08-28 都复用 08-14，下一 fit 约 09-11）。脚本取 manifest 中 `<= 信号日` 的最新 fit 日即可。

出分（秒级～数分钟，加载全市场以命中缓存，**不训练**）：

```powershell
python -m live.predict_from_wf_models --as-of-date <信号日> `
  --model-dir results\xgb_h5_sizeind_w156_nob_wf_<日期> --top-n 100
```

实现要点：复用 `run.py` 数据加载 + `strategies.ml.build_factor_dataset`，命中回测的 `barra_bundle_*` 与 `factor_panel_neut_*`；信号日截面从 `dataset.factor_panel` 取（绕开 `get_cross_section` 因 forward_return 未实现对当日 dropna）。strict 宇宙 + Top-N 与回测 `mask_scores_for_backtest` 同口径。含 B 股会 `SystemExit`。

产物 `candidates_<信号日>.csv` 列：`signal_date`、`suggested_buy_date`（T+1 开盘）、`fit_date`、`rank`、`code`、`name`、`sw_l2`、`circ_mv` / `circ_mv_yi`、`score`。

**同口径校验**：把 `--as-of-date` 设成回测已出分日，对比 `candidates` 与 `ml_factor_scores_*.parquet` 该日 Top100，重合应 >90（曾测 08-21：99/100、spearman=1.0）。

hfq 后复权会因分红追溯调整历史价，隔月重跑 NAV 可整体上移，属正常。

### 10.3 快速备选：last-window（口径不同）

```powershell
python -m live.flagship_last_window --no-download --output-dir results\xgb_h5_sizeind_w156_nob_<日期>
# 已有该目录模型时：
python -m live.flagship_last_window --skip-train --no-download --output-dir results\xgb_h5_sizeind_w156_nob_<日期>
```

只训最新调仓日过去 156 期的一个 xgb 再对数据末日出分。热身窗（~450 日）重算残差，**缓存指纹与全 WF 不同**（曾测同日 Top100 重合仅 ~33%，spearman≈0.09）。**只适合快速看盘，不可与全 WF 回测混用。**

`python -m live.daily_update --model-dir results/<tag> --top-n 30` 是通用增量出分入口，同样**不是**旗舰同口径路径（warmup 窗重算中性化）。前提仍是已有 `models_manifest.json`。

### 10.4 出分是否可信

1. `circ_mv` 末日非空 ≈5500+；candidates 里 `circ_mv_yi` 不全 NaN。  
2. 可交易池末日应数千只（曾见 4000+）。  
3. Top100 市值中位大约小中盘（sizeind 后常 ~20–60 亿量级，随市场浮动）；中位突然 >100 亿要怀疑 Size 中性化失败或 `fillna(0)`。  
4. ST/B=0；北交所 92 可为 0。  
5. score 有梯度，不是常数。  
6. 同口径校验见 §10.2。  
7. 全 WF 才有稳定 IC 序列可读。

排错摘要：circ_mv 稀疏 → 重跑东财市值跑完再 assemble；turnover 截断 → 去掉 `--start` 重算 `compute_market_cap`；Top100 出现 ST → `download_st_history` 后再出分；北交所 92 断更是接口问题，`--bj-only` 只补市值；`download_shares` 若因 pandas option 报错，Size 主路径不依赖它，可 Ctrl-C 后手动补 ST / 换手再 `--no-download` 出分。

### 10.5 不要做的事

- 不要 `--force-refresh` 全量扫五千余只股本。  
- 不要把 `--start` 当 lookback。  
- 不要 kill 后 assemble 半成品（或用 `.bak` 回滚）。  
- 不要每次 live 都从 2021 重训全 WF；口径不变用 §10.2 加载即可。  
- 不要把 hold3 overlay 或 last-window 当旗舰。  
- 不要改旗舰 yaml 超参去迎合「lgbm / 104 期」记忆；调参走 `python -m research.pbo` 后再说。
