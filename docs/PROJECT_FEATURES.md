# 项目特色与设计意图

本文是本仓库的**设计说明书**，面向需要理解「这套框架到底设计了什么」的读者（包括后续把本文压缩成对外简介的人）。它不是入门对照表，也不按「别人做错了、我们修好了」组织。

命令与逐步操作见 [操作手册.md](操作手册.md)。内部实现约定见仓库根目录 [AGENTS.md](../AGENTS.md)。

---

## 1. 项目是什么 / 不是什么

这是一套 **A 股多因子研究与辅助人工选股** 框架：从数据下载、因子计算、信息系数（IC，因子排序与未来收益排序的相关）筛选、机器学习 / 动态加权、分组回测，到按训练折加载模型、输出候选股名单。主入口是 `run.py`；研究筛选是 `python -m research.ic_analysis_v2`；旗舰实盘出分是 `python -m live.predict_from_wf_models`。

**产品定位**：模型输出得分排名与 Top-N 候选池，供人二次筛选后手动下单。框架**不接券商、不自动下单、不构成投资建议**。回测与 live 的数字是研究产物，不是收益承诺。

**不是什么**：

- 不是全自动交易系统或执行网关。
- 不是「一键复现完整历史曲线」的数据快照仓库。行情与财务须自行通过 AKShare 等接口下载；不同机器、不同下载时点、接口字段变更，都会使结果无法逐点复现。
- 不是因子动物园的展示页。进入训练的特征默认来自 IC 筛选后的 YAML 白名单（`config/factor_configs*.yaml`），而不是把注册表里所有名字一股脑塞进模型。
- 不是已经「防过拟合」的黑盒。过拟合检验（概率过拟合 PBO、紧缩夏普 DSR）存在，且历史实验里最优 DSR 很低，提示超参选择偏差真实存在。

数据流的压缩描述：`AKShare → data/raw/*.parquet（含退市股）→ 清洗收益与涨跌停掩码（内存）→ 财务/行业按当时可观测信息对齐 → IC v2 筛选 → 因子白名单 → Walk-Forward / 动态加权训练 → 得分面板 → 分组回测 → results/<tag>/`；live 再按折加载同一批模型对最新信号日出名单。

## 2. 问题设定与 A 股约束

框架的形状来自 **A 股市场微观结构与披露制度**，而不是抽象的「多因子模板」。下面这些约束决定了数据、因子、标签、回测和 live 为什么要分层，而不是合成一条「可交易收益」了事。

### 2.1 涨跌停

主板约 ±10%、创业板/科创板约 ±20%。涨跌停日的账面收益是**被规则截断的数字**，不代表未受限的供需成交。若把它当作普通日收益去算动量、波动率或市场暴露，会系统性低估波动、扭曲相关。框架把这一事实拆成多层处理（见 2.6），而不是在一个函数里「删掉涨跌停股票」。

另外存在**一字涨停**（开盘即涨停且全日锁住）：次日若要以开盘价买入，实际上买不进。回测执行层拦截这种情况，并向后回填名单；研究侧的训练标签默认**不**因此把整段前瞻收益抹掉（见 2.6 与第 7 节）。

### 2.2 T+1 与信号时点

A 股当日买入不能当日卖出。本框架的默认假设更进一步、也更接近「收盘后看盘、下一交易日开盘买」的人工流程：

- 信号在交易日 **t 收盘后** 产生（数据末日 = 信号日）。
- 买入发生在 **t+1 开盘**。
- 前瞻收益（`forward_return`）在有开盘价时定义为 `收盘[t+N] / 开盘[t+1] - 1`，持有约 N 个交易日（`--horizon`：5≈周、10≈双周、20≈月、60≈季）。

IC、机器学习标签、回测执行共用这一时点定义。没有开盘价时才退化为 `收盘[t+N] / 收盘[t] - 1`。

### 2.3 停牌、零成交、次新

停牌或成交量为零的日子没有可成交价格路径。因子滚动窗口用缺失跳过；回测把停牌日组合收益记为 0（净值持平），而不是用前后收盘硬接一段虚假收益。次新股上市初期噪声大、涨跌停规则与流动性也不同，IC/可交易池默认要求上市满 `IC_MIN_LISTING_DAYS=252` 个交易日。

### 2.4 ST、退市与幸存者

若股票池只保留「今天还在交易、名字里没有 ST」的公司，历史上退市、戴帽又摘帽的路径会从样本里消失，回测与 IC 都会偏向幸存者。框架因此：

- 下载并保留退市股的行情（`python -m data.download_delisted`）。
- ST 按**日期**查询，而不是用当前简称做一张永远不变的黑名单。
- 深交所有带日期的简称变更，精度较高；沪市/北交所没有公开的带日期接口，只能从上市日起保守标记（见第 10 节）。

### 2.5 财务披露滞后与行业变更

季报、半年报、年报的**报告期**（例如 3 月 31 日）不是市场可用来定价的日期。法定披露截止大约是：一季报/三季报约报告期后 30 日、半年报约 60 日、年报约 90 日（年报法定窗口更长，实现取偏保守的近似）。在公告日前把报告期数字往前填，等于用未公开信息做历史回测。

行业分类会随公司主业、并购和申万修订而变。用「今天的行业」回填十年前的截面，会把未来的行业归属泄漏进历史中性化与分行业模型。框架用带生效日的行业面板做 as-of 查询。

### 2.6 可交易性分层（四套语义）

这是本框架最核心的产品决定之一：**「这一天这个因子值是否有经济含义」「这一天这只股票是否进入研究样本」「标签是否假设能成交」「回测/实盘能不能买到」不是同一个问题。** 默认研究口径（research v2）如下。

| 层 | 做什么 | 默认 | 为什么分开 |
|----|--------|------|------------|
| **因子收益** | 量价因子用清洗后的日收益（`clean_ret`）：涨跌停日记为缺失 | 始终如此 | 截断收益会污染动量/波动/Beta；因子面板缓存可与执行规则解耦、跨口径复用 |
| **信号日研究池** | IC/ML 可交易掩码（`build_ic_tradability_mask`）仍剔除 ST、停牌、零成交、次新、已退市 | **不**因当日涨跌停剔除（`TRADABLE_EXCLUDE_LIMIT_SIGNAL_DAY=False`） | 涨跌停本身是可学习的截面状态；训练池若在信号日剔光涨停股，模型看不到这类股票 |
| **训练/IC 标签** | 前瞻收益默认**不做**成交掩码（`FWD_RETURN_EXEC_MASK=False`），仍做截面缩尾 | 研究默认 | 标签若按「买得进」再滤一遍，会与研究池膨胀、样本选择纠缠；成交约束留给回测 |
| **回测成交** | 买日一字涨停买不进、卖日涨跌停卖不出 | 始终拦截 | 这是执行真实性，不是样本定义 |
| **回测得分宇宙** | 默认 `strict`：回测前把得分裁回「严格可交易 ∩ 标签在执行口径下可用」 | `--bt-score-universe strict` | 研究训练池更大，若直接拿来做等权基准和分组，会抬高基准、污染 Q 组比较 |

另有一个稀疏因子 **涨跌停状态**（1=跌停 / 2=中性 / 3=涨停，涨停优先），经截面缩尾与标准化后进入特征，专门编码这一状态，而不是靠「从池子里删掉」来处理。

旧的严格执行口径可用 `--tradable-strict`、`--label-exec-mask` 或 `--tradable-limit-mode strict` 恢复。换口径须重跑 IC（checkpoint 后缀 `_tmr_v2`），不可与旧结果直接比。

## 3. 数据层

数据是研究的约束条件，也是 live 最容易静默出错的地方。本节写**主路径、PIT 怎么接、增量运维有哪些已知陷阱**。

### 3.1 行情：后复权与不复权

日常拉两类价格：

- **后复权 OHLCV**（`*_hfq`）：训练、量价因子、回测持仓净值。后复权会因分红除权**追溯改写历史价**，同一套代码在分红季后重跑，旧净值曲线可能整体上移；跨次比较必须同一复权基准。
- **不复权**（`prices_raw`）：换手、部分价值因子分母、市值校验。日更默认可以不把 raw 当主路径；东财 raw 不可用时可用新浪日线补缺口（`python -m data.backfill_prices_raw_sina`），上线前用覆盖率函数验收。

清洗在内存中完成、不改磁盘：去重、零/负价、单日涨跌幅过大、孤岛刺针置缺失，短缺口最多前向填充约 5 个交易日（模拟短停牌）。涨跌停识别区分主板与创/科阈值，并标一字板。**成交量单位是手**（1 手 = 100 股）；换手 = `(成交量×100) / 流通股本`。

### 3.2 市值与换手（两条链，不要混）

- **市值主路径**：东财日频 `python -m data.download_stock_value_em`，写入流通市值 `circ_mv`、总市值 `total_mv`（元），顺带 `pe_ttm` / `pb`。Barra 的 Size 读的就是东财流通市值的对数，缺流通则用总市值；**不再用总资产代理市值**。估值因子尚未全部切到这套日频字段。
- **换手路径**：`python -m data.download_shares` 拉股本，再 `python -m data.compute_market_cap` 算 `turnover_rate`。自算市值落 `*_computed`，只作校验/兜底，不是 Size 主源。旧的 `download_market_cap` 已弃用。

Barra 与中性化必须显式传入市值/换手面板；不传会降级（Size 退回总资产对数、流动性退回对数成交量、回归退回等权），并打警告。小样本对照：`python -m data.validate_market_cap`。

### 3.3 股票池、退市、ST、交易所边界

- 列表合并沪深（及元数据中的退市记录），保留退市股与 ST，供按日过滤，而不是在入口一次性删光。
- **B 股**（沪 900、深 200）与 A 股计价、涨跌停和投资者结构都不可比，生产宇宙剔除；含 B 股进入旗舰 Top-N 会直接失败。这是宇宙定义，不是「特色卖点」。
- **北交所**：代码 8 开头的新三板/北交所路径默认剔除；**92 开头保留**，但东财行情可能断更，属数据源问题，不是过滤漏了。
- ST：`python -m data.download_st_history`。深交所精确历史；沪/北为保守回退（`sh_bj_current_st_conservative_fallback`）。日更**不会自动**刷这张表；过期会把新戴帽放进候选名单。

### 3.4 行业 PIT

`python -m data.industry.download_industry` 产出 `industry_map_panel.parquet`：每只股票一段 `(生效日, 结束日, 申万一级/二级)`。下游按截面日期 as-of 取值。`--barra` 时缺少该面板直接报错；仅 `--allow-static-industry` 允许退回「当前行业一张表」，结果含未来信息，不可与严格口径比较。申万 2021 版分类回填更早年份时，早期段用的是现行分类而非当年市场认知，这是数据源限制。

### 3.5 财务 PIT

主下载接口给出的「日期」是**报告期**，没有可靠的首次公告日。同花顺/东财业绩快报一类「最新公告日期」往往是**修订日**，接入主链会把更晚的修订泄漏到更早的日期，因此**不接入**主路径。

实现（`utils/pit_align.py`）：把报告期平移到法定披露窗口下界（一季报/三季报 +30 日、半年报 +60、年报 +90），再 pivot 并前向填充到日频。长表若自带 `ann_date` 则优先用真实公告日。业绩预告类事件因子本身带公告日，按公告日放入信号并限制前向持续期——这是财务类里「有真实时点」的路径。

财务清洗包括去重、ROE 极端值、每股净资产/总资产非正、删除报告期晚于「今天」的行。科目深度有限（见第 10 节）。

### 3.6 市场代理与基准

中证全指（`data/raw/csi_all.parquet`）用作市场收益、Barra Beta/残差波动的回归对象、以及仓位体制里的趋势/波动信号。回测图另对比沪深 300、创业板指和全样本等权。不要对指数 OHLCV 整表做降维再当「一条收益序列」——须取收盘价列。

### 3.7 扩展数据与停更

融资融券明细、龙虎榜、解禁、回购、大宗、股东户数、高管增减持、机构持仓、研报等已有下载与注册，覆盖不均。北向持股约 2024-08-19 后停止披露：默认不加载进 IC/`run.py`；若显式使用因子，停更后置缺失并警告。东财大单净流入曾注册，因全市场长历史拉不稳已标弃用，待更稳的资金流源再启用。THS 资金流多为截面排行快照，没有个股多年日频，不能当生产长样本。

### 3.8 增量更新：运维特色与覆盖率陷阱

日常增量**不要**把「最近 N 天」当成 `--start` 去覆盖历史，也不要 `--force-refresh` 全量扫股本。旗舰手册中的最短顺序是：行情 → 东财市值 → ST 历史 → 换手（`compute_market_cap` 不带 `--start`）→ 股本按过期天数刷新。

已知会静默毁掉 live 质量的陷阱：

1. **稀疏 assemble**：东财市值增量没跑完就拼宽表，`circ_mv` 末日非空会从五千余只塌成几百只，Size 与中性化失真，大票异常变多。
2. **换手 lookback 截断**：`compute_market_cap --start` 若传到最近两周，前向填充起点被截断，`turnover_rate` 可能只剩几十行。
3. **ST 表过期**：沪市新戴帽靠手动刷 `download_st_history`。
4. **股本中途中断**：全量刷新中间落盘若丢掉未完成旧行会截断 parquet；启动前有 `.bak`。股本按 `refresh_stale_days`（默认 30）增量，禁止「这只曾经成功过就永远跳过」。
5. **北交所 92 断更**：单独 `--bj-only` 补市值；行情仍取决于接口。

上线前至少核对：流通市值末日覆盖、可交易池规模、ST/B 是否混入 Top-N、换手行数是否与行情日期对齐。细节与期望数量级见 [操作手册.md](操作手册.md) §10。

价格清洗、单位、覆盖率对齐的审计过程见 [PIT_AUDIT.md](PIT_AUDIT.md)。

## 4. 因子层

### 4.1 注册中心与白名单

所有能进管线的因子必须出现在 `get_factor_registry()`（及 special 注入包）里。模块大致覆盖：基础量价与财务、第二批 alpha（行业动量、特质波动、融资等）、技术指标、WorldQuant Alpha101 精选、涨跌停派生、分数差分动量、市场级状态（已不再作为截面特征灌进 X，见 4.7）。Barra 九风格**默认不进选股注册表**，只作 IC 纯化与特征残差化的控制变量。

`run.py --factor-config` 只保留 YAML 白名单中的 alpha；缺源的因子自动跳过。事件/规模/稀疏包通过 `--special-factors` 在白名单过滤之后注入训练（见 4.6），**不会**自动改 YAML。`--mode dynamic` 禁止 special 注入，避免和 ICIR 加权轨道混在一起。

### 4.2 方向与标准化

因子函数内部已经按「**越高越好**」取好方向，后续 IC、线性权重和模型不再二次翻符号。线性模式才使用 `FACTOR_WEIGHTS`。

每个截面因子出口统一：

1. 截面 winsorize 1%（缩尾极值）；
2. 截面 z-score，裁剪约 3 倍标准差。

市场级、仓位体制类时序特征用滚动 z-score，**不做**截面标准化：全市场同一天几乎同值，截面 IC 无意义。机器学习取截面时，缺失在 z-score 空间填 0（表示截面中性）。

### 4.3 清洗收益的业务含义

量价类因子（动量、波动、Amihud、Barra 的 Beta/残差波动/动量等）必须使用清洗后的日收益（`clean_ret`），而不是把后复权收盘价直接做百分比变化。

**含义**：涨跌停日的账面涨跌幅是规则截断的结果。把它当作「这一天的真实收益」会让高波动、常触板的股票在动量和波动上系统性失真，也会污染对市场指数的回归。框架在这些日子把收益记为**缺失**，滚动统计自动跳过，相当于「这一天没有未受限的成交收益」。涨跌停作为**状态**另有掩码和「涨跌停状态」因子；作为**价格路径**则在回测执行层处理。两件事不要合成一次 `pct_change`。

### 4.4 财务与行业在因子里如何对齐

财务类：先 PIT 平移再前向填充到日频，禁止按报告期直接填到公告之前。机构持仓等季报同样走 PIT。行业动量、行业相对强度、分行业训练、Barra 行业哑变量应使用面板 as-of，而不是静态「当前行业」。

### 4.5 Barra 风格定义与 WLS 残差化

Barra 在本仓库里是**风险/风格控制变量**，不是选股信号。口径在 2026-07-29 重写，市值源 2026-07-30 切东财；旧的纯化 checkpoint、残差缓存和「纯 IC」白名单不可与新口径比。

| 风格 | 现行定义（按文档） |
|------|-------------------|
| Size | `log(流通市值)`，缺则总市值 |
| NonlinSize | Size 的平方，再对 Size 正交 |
| Liquidity | 63 日与 252 日**换手率**等权平均（不是成交量） |
| Leverage | 单一资产负债率（DTOA） |
| Growth | 营收同比 50% + 净利润同比 50%；各腿先 1% 缩尾再 z-score，然后合成 |
| Beta / ResVol | 对**中证全指收盘**做半衰期 63 日加权回归；残差波动含 252 日 HSIGMA |
| Momentum | RSTR，240/20 窗口、半衰期 60 日加权 |
| Value 等 | 与财务 PIT 对齐；出口对每个 Barra 因子做行业去均值，减少控制变量之间的残余行业成分 |

截面回归统一为 **加权最小二乘（WLS）**，权重为市值的平方根（`utils/wls.py`，`barra_regression_weights`）。无市值面板才退回等权普通最小二乘并警告。IC 纯化（`research/ic/barra.py`）与特征残差化（`residualize_panel`）共用这套回归。

`--feature-neutralize`（`run.py` 默认开）在 `build_factor_dataset` 出口对每个稠密因子做风格+行业残差，使 **ML 特征与 IC 的「纯 IC」同口径**。否则筛选阶段认为「去掉市值/行业后仍有 alpha」的因子，训练时仍带着系统性敞口，模型很容易学成「小盘 + 某行业」而不是残差 alpha。旗舰配方用的是 **Size + 申万二级**（`neut_controls=size_industry`），不是九风格全开。稀疏/事件/市值 alpha 包默认**跳过**残差化，避免把本来就稀、或本来就要保留的规模暴露洗掉。

标签也可选 `label_mode='barra_residual'`（对 **y** 残差化）；默认旗舰是截面排名（`cs_rank`），与特征中性化是两件不同的事。

### 4.6 稀疏、事件与 special 注入

IC 把因子分成稠密轨与稀疏轨（龙虎榜、涨跌停事件、解禁、高管、大宗、业绩预告等）。稀疏因子经常大面积缺失，不能和稠密因子抢同一套 t/FDR 阈值。生产上推荐 `--special-factors sparse --sparse-from-ic <IC JSON>`，只注入 JSON 里 `factors_sparse` 的名字。Ridge 对稀疏列做方差对齐（有值单元格标准差拉到约 1），避免 L2 惩罚把系数压没；树模型不额外缩放。详见 [操作手册.md](操作手册.md) §5.4。

### 4.7 分数差分、仓位体制、组合层

- **分数差分动量**（AFML 第 5 章，`utils/fractional_diff.py`，默认 d=0.4）：在尽量保留长期记忆的同时让序列更平稳，作为动量族的补充，不是默认主信号。
- **仓位体制**（`--position-regime`）：市场级标量「买多少」（趋势/波动/广度合成目标敞口），与截面「买谁」分开。旧的「轮动_* 灌进特征矩阵」和广播市场/HMM 进 X 已退役（截面方差为 0，对排序无信息）。见 [操作手册.md](操作手册.md) §5.1。
- **组合权重**（`--portfolio-opt`）：在已经选出的集合上分配权重（等权/得分/排名/逆波动等），默认等权以保持与历史路径一致。见 [操作手册.md](操作手册.md) §5.2。

### 4.8 残差化缓存键

急切构建数据集与 rolling-pool 懒加载共用 `factor_panel_neut_*`（版本 `neut_v6`）。键包含：因子名、持有期、调仓频率、股票宇宙指纹、调仓日历指纹、Barra/行业/WLS 指纹。**不同 horizon 或不同调仓频率绝不可共用同一份残差面板。** 换口径须删除 `data/processed/factor_panels/factor_panel_neut_*.parquet` 与 `barra_bundle_*/`。因子面板对行业指纹只签一维（优先申万二级 Series），避免 IC 传入整表、ML 传入 Series 时因维数不同而假缓存未命中。

## 5. IC 筛选（生产级）

生产路径是 `research.ic_analysis_v2`（`logs/driver.py` 默认调用）。v1 单体保留为后备。筛选结果写入 `research/output/selected_factors_h*.json`，再同步到 `config/factor_configs*.yaml`。训练只吃白名单。

### 5.1 在算什么

每个调仓日：因子截面与前瞻收益的 Spearman 相关（先排序再 Pearson，向量化）。调仓日与训练/回测一致：取自然周或自然月的**最后一个实际交易日**（`groupby(period).last()`），不用日历上的周五/月末虚日。约定 Q1=最低分、Q5=最高分；IC 为正表示高分一侧更好。

可选 `--barra`：先对因子做 Barra+行业 WLS 残差，再算「纯 IC」。有纯 IC 时以纯 IC 为筛选主判据，原始 IC 作诊断。行业必须是 PIT 面板。

### 5.2 为什么需要一整套门，而不只是「IC 均值」

同时检验几十到上百个因子时，只看均值会稳定地选出噪声。各门对应不同失效模式：

| 机制 | 意图 |
|------|------|
| **Newey-West HAC t**（默认 \|t\|≥2.5） | IC 序列有重叠持有期，相邻观测不独立；普通 t 会夸大显著性 |
| **Benjamini-Hochberg FDR**（默认开） | 控制「这一批里假阳性比例」，而不是单次检验的第一类错误 |
| **\|IC\| 与 ICIR 合取** | ICIR = IC 均值 / IC 波动；只要均值不要稳定性，会留下高波动的运气因子 |
| **相关去重**（默认 \|corr\|>0.7 留 ICIR 更高者） | 拥挤与共线：多个名字测的是同一风险；聚合可用 max/p95/mean |
| **滚动 ICIR / 衰减表** | 全样本均值可能来自早年；半衰期、近远窗对比用来标衰减，而不是假装因子永远有效 |
| **扣成本 IC** | 换手高的因子账面 IC 好看，扣掉交易成本后可能消失 |
| **long_share（稠密门，默认 >0.4）** | 分组回测里多头贡献占比；有的因子空头腿贡献几乎全部「有效」，多头不可用。与 \|IC\|∧\|ICIR\|∧t/FDR 合取，在相关去重之前。分组前若时序纯 IC 均值为负会翻转残差方向再算 Q5/Q1，避免「负 IC 未翻转」被标成无效 |
| **稀疏轨** | 事件因子不走 t/FDR；改用同向胜率 + 触发日截面命中率，过线后再相关去重 |
| **可交易掩码** | IC 只在研究可交易池上算，避免停牌/ST/次新制造虚假相关 |
| **市值缩域**（`--cap-band`） | 全市场有效的因子在小微盘上可能反向；缩域后单独筛选、单独训练 |
| **次新下限 252 日** | 降低上市初期异常收益对 IC 的贡献 |
| **Gram-Schmidt**（默认关） | 正交化后的因子给动态加权等轨道用；需显式打开 |

新兴因子轨（近窗提升）默认只观察、不进生产 `factors`。衰减/风格逆转默认是标注，不是自动扔出白名单。h5 与 h20 生产筛选应使用同一套开关，避免两个 horizon 的白名单口径分叉。

### 5.3 产物、断点与防覆盖

`--save` 写出汇总、逐年、纯 IC、筛选 JSON；JSON 含宇宙规模、IC 序列长度、样本区间、配置快照、`tradable_mode` / `label_exec_mask`。checkpoint 可 `--resume`；`--fresh` 才清空。增量 `--only-new` / `--factors` 合并已有 IC 序列。写入前对既有 CSV/JSON 归档到 `_archive/`，避免小样本冒烟覆盖全市场产物。不要在生产 period（5/10/20/60）上用两三个因子做会写同一文件名的试验。

## 6. 模型与 Walk-Forward

### 6.1 模式在加权什么

| 模式 | 行为 |
|------|------|
| `linear` | 配置里的静态因子权重 |
| 单模型 `ridge` / `lgbm` / `xgb` / `cat` / `rf` / `mlp` | 时间向前滚的 Walk-Forward，用模型得分排序 |
| `ensemble` | 多训练窗口 × 多模型 → **按 IC 加权后的 z-score 平均**（不是把排名盲平均） |
| `dynamic` | 不训树，按滚动 ICIR 给因子加权 |
| `industry` | 申万二级（过小行业合并）各自训练，再全截面排名 |
| `ensemble` + `--blend-dynamic` | ML 得分与动态加权得分先各自百分位排名再混合 |

当前**旗舰不是 ensemble 盲平均**，而是单模型 xgb + Size/行业中性化 + 长训练窗 + 每 4 期重训（见第 8 节）。

### 6.2 purged + embargo 的含义

Walk-Forward 每个预测调仓日 `idx` 只用该日之前的样本。前瞻收益标签覆盖未来 N 日，若训练截止日紧贴预测日，训练标签与预测日的持有窗口会**时间重叠**，等于用含未来信息的标签拟合。处理分两步（AFML 第 7 章）：

- **purge**：从训练集中丢掉与验证/预测标签窗口重叠的样本；
- **embargo**：在边界再留一段禁运带，宽度由持有期换算（`hold_period_to_embargo_periods()`）。

即使关掉独立验证集（`val_window=0`），purge 与 embargo 仍然在。

### 6.3 窗口、验证集与重训节奏

默认（研究向）：多个训练窗（日历月，再按调仓频率换成期数）、验证窗约 6 个月。**两窗共用紧贴预测日的近期验证集**：验证 `[idx-V, idx)`，训练 `[idx-V-W, idx-V)`，只是 W 不同。`val_window=0` 时训练 `[idx-W, idx)`、无独立验证；此时多窗必须 `wf_selection=average`，不能再按验证 IC 挑窗。

**默认 `--retrain-every 4`**：周频调仓时约等于每月重训一次，中间三期复用上一折模型。每期重训用 `1`。训练诊断表记录每期是新拟合还是复用、对应拟合日。样本可加指数时间衰减；旗舰把衰减关掉（窗内等权）。`mlp` 不支持样本权重。

### 6.4 集成、解释与 rolling-pool

- 多窗 × 多模型默认 **IC 加权 z-score**，让近期更有效的模型/窗口占更大权重。
- **聚类特征重要性**（AFML 第 6 章）：高度相关的因子先聚类再算重要性，避免同类因子把重要性拆碎。
- **SHAP** 默认关（`--shap`），折内树/线性解释，与普通 FI、聚类 FI 并存。
- **rolling-pool**：每一期调仓日 t 的特征列 = 当日池 `pool_t`（有上限），该期训练/验证/预测共用这组列，**禁止**把三窗出现过的因子并成一张大表。生成日程时，决策日 t 的 IC **只用严格早于 t 的样本**（当日 IC 依赖尚未实现的 t→t+h 收益）。消费侧 as-of `<= t` 因此是安全的，不要再 shift 一次。缺面板时默认直接报错（`--rolling-pool-strict`），禁止整列缺失填 0 当成常数特征。产物 tag 带 schedule 指纹，避免和固定池实验互相覆盖。内存上用粘滞 LRU：每期只确保当前池在缓存中，不每期把其它因子全部释放。

### 6.5 Live 与回测同口径（产品设计）

生产路径：

1. 全量 Walk-Forward 加 `--save-models`，每个拟合日存模型与 `models_manifest.json`（路径、窗口、日期、特征名、是否中性化、控制变量）。
2. live（`live.predict_from_wf_models`）按 **retrain_every 的折调度**加载「服务该信号日」的那一折：例如每 4 期重训，8 月 28 日的信号加载 8 月 14 日拟合的模型，中间两周复用，与回测诊断表一致。
3. 出分复用与回测相同的数据加载和 `build_factor_dataset`，命中同一套 Barra bundle 与残差缓存。信号日截面绕开「标签未实现就 dropna」的门控，否则最新一天永远没有分。

**最新窗口现训**（`live.flagship_last_window`）是快路径：只在最近 156 期上训一个模型。热身窗、Barra 指纹、残差缓存与全量回测不同，同日 Top-N 可以差很远。它不能用来「验证」回测净值，只适合临时看盘。通用增量入口 `python -m live.daily_update` 同样不是旗舰同口径路径（见 [操作手册.md](操作手册.md) §10.3）。

换中性化、持有期、调仓频率必须重跑全 WF；旧 manifest 不可复用。日常 live 在口径不变时只做增量数据 + 按折加载，不必从 2021 重训。

## 7. 回测与成本

唯一回测入口是 `backtest/quantile.py`（模块化：execution / portfolio / return_engine / turnover / benchmark / report）。由 `run.py` 在得分生成之后调用。

### 7.1 调仓日历与买入假设

调仓日 = 所选频率下每个周期的**最后一个真实交易日**，与 IC/ML 共用 `utils/rebalance_dates.py`。horizon 到频率的映射：约 5 日→周五周频，10 日→双周，20 日→月。信号日收盘排序，**下一交易日开盘**成交（有开盘价时）。持有到下一期信号对应的执行日。净值按真实 buy-and-hold：执行日从开盘到收盘，其后收盘对收盘；停牌日记 0。

### 7.2 分组、Top-N 与基准

`pd.qcut` 升序切 Q1–Q5（分位重复时 `duplicates='drop'`）。另出 Top-N（配置 `N_STOCKS`，旗舰技能度量常用 100；实盘人工未必买满）。对比全样本等权、沪深 300、创业板指。IC>0 时预期 Q5 优于 Q1；单调性是诊断，不是保证。

### 7.3 成本结构

默认大约：佣金双边各 1bp（`COMMISSION_RATE=0.0001`）、卖出印花税 5bp（`STAMP_DUTY=0.0005`）、滑点 0（小资金手工单的假设）、买卖价差 10bp（`BID_ASK_SPREAD_BPS=10`，`--bid-ask-spread`）。成本在调仓执行日从净值扣除。换手明细可导出。不计成本的纸面多空不是默认输出口径。

### 7.4 执行为什么必须和「信号日可买」分开

研究池回答：「这个截面上，模型有没有权利给它打分、标签有没有定义。」回测执行回答：「假设按次日开盘下单，这笔能不能成交。」

一字涨停：开盘价已经是涨停价，排队买不进 → 跳过并按排名回填。卖日涨跌停：卖不出 → 当期继续持有。ST、上市天数由交易规则过滤。把这两层合成「训练时就删掉所有涨停股」，模型会失去一整类截面；把执行层关掉，净值会包含买不进的收益。

**strict 得分宇宙**：落盘分数仍可保留训练覆盖（方便对照）；回测前 `mask_scores_for_backtest` 裁到严格可交易且执行口径下标签可用。否则研究池更大的等权基准会看起来更强，Q 组超额被稀释或扭曲。`--bt-score-universe train` 才与训练池一致，仅用于诊断。

可选：组合优化、换手上限、仓位体制缩放敞口。这些是回测套壳，不改变截面模型本身。人工 overlay 见操作手册 §5。

## 8. Live / 生产

定位：默认周五收盘后出信号，下一交易日开盘买；人看 Top100 / Top30（或更短名单）；T+1；**不自动下单**。

### 8.1 旗舰配方

名称 `xgb_h5_sizeind_w156_nob`，配置 `config/flagship_xgb_h5_sizeind_w156_nob.yaml`。要点：xgb、持有期 5（周频）、训练 156 期、无独立验证、每 4 期重训、无时间衰减、标签截面排名、特征中性化为 Size+申万二级、稠密白名单 + IC 选出的稀疏包、买卖价差 10bp、剔除 B 股、保留北交所 92、回测得分宇宙 strict。逐步命令、覆盖率数字与排错见 **[操作手册.md](操作手册.md) §10**。

### 8.2 推荐步骤

1. 按第 3.8 节增量更新并自检覆盖率。
2. 口径不变且已有 `models/models_manifest.json`：`python -m live.predict_from_wf_models --as-of-date <信号日> --model-dir results/<全WF目录> --top-n 100`。
3. 口径变更或首次：先 `run.py ... --save-models` 全 WF，再走上一步。
4. 同口径校验：把 as-of 设成回测已有得分的日期，对比 Top-N 重合与排序相关（手册中有接近逐点重合的记录）。
5. 人工 overlay：行业拥挤、事件、流动性、是否跟满 Top-N，属于人的职责，不是模型输出的一部分。

快速备选 `flagship_last_window` 与 `daily_update` 见第 6.5 节：更快，调度和缓存指纹不同。

增量日更链路会在热身窗（默认约 450 日）上重算长窗因子与当日残差，避免全历史重训；EWM/RSTR/52 周新高等依赖足够热身。append 后的因子面板指纹与全量 `run.py` 不完全相同，下次全量会因签名失配重算——增量是捷径，不是研究缓存的替代。

## 9. 工程与可复现

### 9.1 结果目录与 tag

实验产物在 `results/<tag>/`（默认 gitignore）。tag 大致为 `{mode}_h{horizon}[_w{窗口}][_m{模型}][_blend][_中性化/稀疏等后缀]`；rolling-pool 再追加 schedule 缩写与短哈希。同参数不同池不得共用目录。典型文件：得分 parquet、净值/逐年/风险指标、四宫格图、Top 持仓、模型指标 JSON、逐期 IC、可选 SHAP、`models/` 与训练诊断。

### 9.2 缓存与指纹

| 缓存 | 作用 |
|------|------|
| 因子面板 `factor_panel_*` | 按输入签名；live append 会标 `live_appended`，全量路径随后重算 |
| 残差 `factor_panel_neut_*` | `neut_v6` + horizon + 频率 + 宇宙 + 日历 + Barra/WLS |
| Barra bundle | 风格因子与权重，换定义必须删 |
| IC checkpoint | `_tmr_v2` 等后缀；换可交易/标签口径须 `--fresh` |
| IC 产出归档 | 覆盖前复制到 `_archive/` |

换 Barra 定义或市值源之后：删 neut 与 barra_bundle，删 `barra_pure_h*.pkl`，重跑 `--barra`，并承认旧 JSON/YAML/实验结论不可比。

### 9.3 编排与过拟合

`logs/driver.py`：IC v2 → 同步 YAML → 按预设批量 `run.py`。`logs/analyze_results.py` 汇总。`python -m research.pbo` 计算 PBO 与 DSR，并接入分析结果。历史一批实验里最优 DSR 约 0.025，应解读为**警告**而不是装饰。

并行与内存：32GB 机器建议训练/IC/动态加权工作进程为 1；不要叠 `driver --parallel-ic` 与高 `--workers`。

CLI 默认已含特征中性化、10bp 价差、research 可交易、`cs_rank`、strict 得分宇宙、`retrain_every=4`。日常 `--help` 精简，高级与弃用开关在 `--help-advanced`。

### 9.4 测试覆盖的设计点（不是测试清单）

## 10. 已知限制与诚实边界

把这些写成特色的反面：框架**承认**下列近似与空白，而不是假装已经「机构级数据」。

1. **财务无可靠首次公告日**。法定披露窗口是保守近似：实际公告往往更早，因子会晚几天用上季报；若窗口仍宽于真实公告，理论上仍可能有少量前视。修订/重述未建模。yjbb「最新公告日」故意不用。
2. **沪市/北交所 ST 不是精确历史**。自上市日起保守标 ST 会误伤从未戴帽的区间，也会漏掉「接口没有日期」的新戴帽——后者只能靠勤刷 `st_history` 缓解，不能当交易所级事件库。
3. **行业早期段是申万新版回填**，与当年交易者看到的分类不必一致。静态行业退化路径含 PIT 泄漏。
4. **北交所 92 行情可能断更**；北向持股停更后默认不进生产因子。
5. **东财/AKShare 限流与半成品宽表**：覆盖率必须自检。仓库不附带 `data/raw`，完整曲线不可跨机器逐点复现。
6. **辅助字段清洗薄**：成交量/资金流等以转数值和去重为主，极端异常检测不完整（见清洗审计）。财务科目浅，商誉、审计意见、分红稳定性、一致预期、筹码等未充分纳入（见数据缺口文档）。
7. **研究标签默认包含涨跌停日的前瞻收益**，与因子侧 `clean_ret`、回测 execution 三套语义并存；解读 IC 与 Q 组时必须记住默认是 research 口径。
8. **过拟合**：PBO/DSR 显示单次最优实验不可信。旗舰超参不应在没有样本外纪律的情况下随意拧。`--tune` 存在，不自动等于更真的 alpha。
9. **中性化失败会静默偏向大票**：残差化若退化或流通市值覆盖塌缩，Size 暴露会漏回得分，Top-N 市值中位数异常升高。live 必须看覆盖率和市值结构，不能只看分数列是否非空。
10. **last-window / daily_update ≠ 回测**。热身窗与缓存指纹不同。
11. **hfq 追溯调整**使「同一 tag 隔月重跑」的净值不必重合。
12. **产品不做杠杆>1、不做券商路由、不把 Top-N 自动当成必买清单**。仓位体制历史实验里平均敞口可以明显小于 1；满仓跟 Top100 的回撤与换手由使用者自己承担。
